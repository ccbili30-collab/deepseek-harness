# 迁移任务书：桌面端界面体系 → 新体系

> 这份文件是**接手者的第一份读物**，也是防跑偏的锚点。
> 配套文件：[契约.md](契约.md)（接口与数据格式）、[验收场景.md](验收场景.md)（怎样算做完）、[工作表.md](工作表.md)（谁在动哪些文件）、设计稿 [workbench-v2/README.md](workbench-v2/README.md)。
> 任何与本文冲突的临时想法，以本文为准；要改本文，先问用户，再在末尾「变更记录」留痕。

## 0. 接手速读（5 分钟）

**一句话**：把桌面端做成「AI 创作工作台」——用户在画布里**直接动手**创作 OC / 世界观 / 文稿 / 时间线，AI 在旁边当第二双手；做好的东西能打包到手机上玩。

**你现在在哪**：基础设施已初见雏形（卡存储、AI 卡工具、创作库、sidecar、画布外壳），界面是旧体系（工作台 + 功能台）。要迁到设计稿 `workbench-v2/` 的新体系（内容树 + 画布标签页 + 对话）。

**开工前必做的 6 件事**

1. 读 §2 决策表和 §3 红线。
2. 读 `工作表.md`，在「正在开工」登记你要动的文件，再动手。
3. 读 `契约.md` 里和你这一步相关的节；读 `验收场景.md` 里本阶段的场景。
4. `git status` 看一眼：工作区有大量历史未提交改动（这是用户的在制品），**不要整体 `git checkout`/`stash`/`reset`**。基线提交由用户决定。
5. 记下类型检查基线：`noven-shell` / `noven-workbench` / `noven-library` / `noven-sidecar` 当前 `tsc --noEmit` 都是 **0 错误**，之后不得增加。
6. 回答 §8.3 的漂移自检五问。

**收工前必做的 4 件事**：跑本阶段验收场景；类型 0 错误；`noven-cards` 的 `node tests/round-trip.mjs`、`noven-docs` 的 `node tests/docs-check.mjs` 全绿；在工作表销记并写日志（做了什么、怎么验证的、遗留什么）。

## 1. 北极星

- 定位：**AI 是笔，握笔的永远是人。** 不是角色扮演产品，更像「创作版豆包」。
- 桌面端 = 创作工作室（做 OC、世界观、文稿、时间线、精美界面）；手机端 = 游玩（另一边在做，**不要碰手机端代码**）。
- 玩家既是游玩者，也是潜在开发者：看到的东西随手能改（玩 → 标注 → 衍生 → 创作是一条梯子，不是两个身份）。
- 用户最看重的是**手作手感**：能直接点、拖、写，而不是只看或只靠对话。「画布只能展示、不能编辑」是我们要消灭的问题。

## 2. 已拍板的决策

| # | 决策 | 理由 / 备注 | 状态 |
|---|---|---|---|
| D1 | 卡和模块是**预制菜**：模块**类型**由我们预制，**实例**由用户或 AI 创建（不是自带的）。Studio 是**现炒菜**：AI 拿最大权限做精美页面。卡不锁住用户的一切 | 用户原话：卡是「最简单的 AI 和人共同使用的工具」 | 定 |
| D2 | **抽屉原则**：编辑不同东西，永不互相阻塞；只有同一个文字块被同时改才冲突，且只拦这一块 | 旧实现是整卡一把版本锁，AI 后台改 B 会让用户保存 A 被拒 | **P0.1 已落地** |
| D3 | 预制模块 v1 **全部放在卡里**（单一的家）；文稿 = `文稿/` 下的 Markdown 文件；作品 = Studio 产物文件 | 避免「卡内卡外两个家」 | 定 |
| D4 | **AI 的改动默认是提案**（草稿 ≠ 正式版，差异叠在画布上，逐条接受/拒绝）；每张卡可开「信任 AI」自动生效（仍可撤销）。信任开关存在**应用侧账本**（`library.json` 的 `cardMeta`），不进卡本体，不随交换包流出 | 提案天然映射到现有 `draft.json`/`card.json` 结构 | 定，**P0.2 待做** |
| D5 | **选中即上下文**：用户在画布选中的东西，以结构化标签写进**用户消息本身**（用户看得见，自然进会话日志） | 仓库铁律：进模型的内容必须能从会话日志重建，不开隐藏通道 | 定，P0.3 待做 |
| D6 | **布局是数据，不是写死的页面**：总览页是「小块清单」，存卡的 `extensions`；默认自动排，用户拖，AI 通过工具改；要完全不同的走 Studio | 解决「每人同一个界面会腻」又不做每人一套 HTML | 定，P3 |
| D7 | **数据层演进，不重写**；**界面层可整体替换**；上游包（`packages/`）允许改，但必须同步改文档和测试、登记工作表 | 卡存储的身份（编号）、Finder 可见、软删除、修订、交换包是反复讨论定下的保证 | 定 |
| D8 | **手机端等桌面全部做完再兼容**：过程中格式可以自由演进，**不为 Android 兼容让路**。但仍要：新数据带 `version`、桌面端能读旧版本、格式写成规范（契约 C3）。Android 现状（读取宽松、编辑保留顶层未知字段、丢条目内字段）只是将来适配的**参考**，不是现在的约束 | 用户 2026-10-06 拍板：做的过程中肯定还会遇到要改格式的风险和问题 | 定 |
| D9 | **红线：不做假功能**。界面上每个按钮要么真能用，要么不出现，要么置灰并写明原因 | 最早的问题就是「看起来好看，点了没用」 | 定 |
| D10 | 空分组不显示；新建世界默认只放一个「设定总览」，其余模块按需长出来 | 空的时间线、地图只会制造压力 | 定 |
| D11 | 视觉以**现有产品设计令牌**为准（浅色、薄荷绿强调）；设计稿定**结构 + 交互**，不抄像素 | 设计稿是图生图，有乱码和错误，标注见 `workbench-v2/README.md` | 定 |
| D12 | 用户界面里不再出现「工作台 / 功能台」这两个词，用「内容树 / 画布 / 对话」；代码里的 `workbench` 命名可以保留 | — | 定 |
| D13 | 插件**不得**用 `session.append` 写自己的事件类型（词汇表不含插件类型，客户端重放日志会拒载）；通知走轮询修订号 | sidecar 踩过的事故 | 铁律 |
| D14 | 卡的身份是**编号**，目录名只是 Finder 里的投影；Finder 改名由扫描接管 | 现有实现，不要破坏 | 铁律 |

## 3. 范围与红线

**做（P0–P3）**：抽屉锁、提案、选中上下文、数据格式 v2（时间线/集合/布局）、内容树、画布标签页、新建流程、起点页、卡页挪进画布、总览（自动布局 → 可编辑）、文档编辑器升级、时间线编辑器、集合编辑器、专用 AI 工具。

**明确不做（本轮范围外，不得做成假的先放着）**

- 地图编辑器（区域编号 + AI 命名 + 笔刷）：没做过原型，立项再说。
- 玩家视角配置（手机界面里放哪些模块）：要和手机端协商协议。
- Studio 的改造（点选页面元素等）。
- 社区 / 首页 feed / 点赞 / 分享 / 市场 / 服务器同步。
- 手机端任何代码。

**红线（违反即停，先问用户）**

1. 不做假功能（D9）。
2. 不重写数据层；不改 `卡/<卡名>/` 的目录布局；不破坏旧 `card.json` 的可读性。
3. 不引入新的顶层概念 / 新名词，除非用户同意。
4. 不让 AI 工具去手写大段 JSON：时间线、集合要给**专用工具**（加事件、加时代、移动事件……），格式由代码保证。
5. 不绕过 locale：用户可见文字一律走类型化词典 + `t`（仓库有 `verify-client-ui-i18n` 门禁）。
6. 不 `git commit` / `push` / 开 PR，除非用户明说；不整体 `checkout` / `stash` / `reset`；不删除用户数据或大目录。
7. 不碰手机端代码；不碰 `Novex-Development` 里的任何东西。

## 5. 目标架构：四根柱子 + 一个壳

**柱 1 抽屉锁**（✅）。按卡串行的写入链 + 可重入；命令直接套用到最新内容；块级期望（`content_ref`）才会冲突。
**柱 2 提案**（P0.2）。提案 = 草稿相对正式版的差异，按模块接受/拒绝；`trust` 开关在账本。
**柱 3 数据格式 v2**（P0.4）。时间线（历法 + 时代 + 数值时间）、集合（自定义字段 + 图片）、布局（总览小块）。放载荷顶层，兼容 Android。
**柱 4 选中上下文**（P0.3）。选中 → 结构化标签 → 写进用户消息。

**壳**：对象登记（客户端服务）+ 内容树 + 画布标签页 + 新建流程。编辑器不自己 `fetch`，只接收数据并发出命令（见契约 C1）。

### P1 外壳（进行中）

- **探针结论（Q2 已答）**：功能台/工作台**不用 fork 上游**。`sidebar.workspaces`（左列内容区）、`rightbar`（右列整个单元格）、`main` 的 `conversation` 键都是可遮蔽槽位：同单元格不同 `priority` 共存，**最小 priority 渲染**（默认 0，我们挂 -100）。被遮蔽条目的 `children` 声明在注册时已生效、随其注册存活——下游 inject 不报错，只是无人渲染。对话列复用 `conversation.content` factory（`ui-subagent` 证明过的嵌入路径），本地 `slots:{views}` 有默认组件可省略。
- 已落地（noven-shell，未实测）：`canvas.tsx`（`main` 键 `conversation` 遮蔽，标签 store persist、起点/卡/文稿/素材四体）、`tree.tsx`（遮蔽 `sidebar.workspaces`：项目头/搜索/分组/＋新建/素材入口）、`chat.tsx`（遮蔽 `rightbar`，`SessionProvider`+`noven.chat` 子槽位嵌 `conversation.content` embedded）、`creation.tsx`（世界/角色/文稿面板）、`tree-api.ts`（轮询源）。`openCard` 改开画布标签；`CardStudio`/`CardEditor` 改收 `card` prop。
- 会话绑定：追踪 `uiSession.adapter.current` 拿 chat 绑定会话；无绑定时自动 `openSession` 最近的工作区会话。项目焦点 = 绑定会话的 cwd。
- 已知偏差：左侧 icon rail（panellist）仍在，旧页（首页/新建/消息/我的）可经它到达——过渡期保留。

| 关系图 / 图集 / 表格 | 对象登记按类型 id 注册，加类型 = 加一条登记，不改外壳 |
| 自定义历法之外的时间单位 | `calendar` 对象用 `unit` + `format` 描述，不写死「年」 |
| 同步 / 市场 | 所有卡操作走命令，修订快照只增不改（已满足），不要引入原地改写的历史 |

## 8. 防跑偏机制

### 8.1 反模式清单（见到就停）

1. 为了「像设计稿」把数据写死在组件里（设计稿里的蛮荒-404、艾莉缇等都是**示例文案**）。
2. 每种对象复制粘贴一套编辑器，而不是走对象登记。
3. 组件里直接 `fetch` 各路由；一律经 `card-api.ts` 这类 API 模块。
4. 让 AI 手写时间线/集合的 JSON。
5. 顺手重构不相关代码；顺手「修」别人在制品。
6. 为通过测试而改测试的期望，却没有产品理由。
7. 把「还没做」画成能点的按钮。
8. 在 `main` 面板里新做整页界面（新体系里的内容都应该是画布标签页）。
9. 破坏已有数据兼容（旧卡打不开）。导出包手机读不了**不再是约束**（D8）。

### 8.2 必须停下来问用户的情况

想改 §2 的决策或 §3 的红线；要改卡的目录布局或交换包的不兼容部分；要删除用户数据；想引入新的顶层概念；预计超出当前阶段范围；需要提交 / 推送 / PR；上游包改动会连带大量文档与测试变更。

### 8.3 漂移自检五问（每阶段开工前先答，写进工作表日志）

1. 我这一步在服务哪个**验收场景**？（编号）
2. 我会不会做出**假功能**？哪些入口是真的、哪些是置灰的？
3. 我有没有**新增概念**或**改了决策**？
4. 我动的**数据**，旧卡能读吗？改了格式有没有升 `version`、有没有同步更新契约 C3？
5. 我是在**演进数据层**，还是不小心在重写它？

### 8.4 阶段门

每阶段结束，在 `工作表.md` 的工作日志写：做了什么 / 对应哪几个验收场景 / 怎么验证的（命令与结果）/ 遗留与风险 / 哪些文件已放开。**没写验收报告，不算完成。**

## 9. 工程守则与已踩过的坑

**仓库规则（摘要，全文见 `AGENTS.md`）**：用户可见文字走 locale 词典；每个导出有 JSDoc；注册都走 `ctx.effect`；空 `catch` 要写明原因；不新增 `as unknown`；改 `packages/` 先读 `docs/architecture.md`；公共 API 是预稳定的——改了就更新所有使用方。

**必须记住的坑**

| 坑 | 症状 | 做法 |
|---|---|---|
| 插件构建链是 `tsc -p tsconfig.json && tsdown` | `tsc` 红了仍会 emit，容易带病上线 | 先 `tsc --noEmit` 看 0 错误 |
| Web 外壳是 Vite 构建 | 线上跑旧 `dist`，新代码不生效 | 用 `pnpm run dev:web`（会重建 Web 客户端包），并验证线上 bundle 里有你的代码 |
| 插件配置字段是 `Volatile` 包装对象 | 当字符串用会崩，被兜底成空 400 | 一律 `.get()` |
| 插件向会话日志写自定义事件 | 客户端重放日志直接拒载 | 禁止（D13）；通知走轮询 |
| 工具输出里有显式 `undefined` 字段 | 「value is not lossless JSON」假失败 | 条件展开，不写 `undefined` |
| 插件加载失败只在终端日志 | 用户端表现为功能凭空消失 | 改了插件后看启动日志，确认无 `failed to import` |
| 客户端路由与服务端路由半截状态 | iframe 显示裸「not found」 | 已有 `probeFrame` 兜底；新增路由时两端一起建 |
| 新插件不会自动加载 | 功能不出现 | 在 `~/.dsh/profiles/web/package.json` 加 `link:` 并在 `cordis.yml` 启用，再重启 |
| 生图 API | sail 余额用尽 `insufficient balance`；qianc 分组被撤 `model_not_found` | 不是代码问题，找用户 |
| `stash@{0}` 仍在 | 里面有 canvas / region-sort 的在制品 | 不要 pop / drop，除非用户说 |
