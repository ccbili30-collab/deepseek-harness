# 自由模块整改计划（HTML / 3D）

> 范围：卡内 `html` 模块（自由界面）与 `free3d` 模块（自由 3D）。
> 定位：它们是整个模块体系的**最大自由层**——结构化模块是预制菜，自由模块是现炒菜。AI 想做一个新东西，默认走这里；只有这里确实做不了，才落文件。
> 状态：待评审。评审通过后按阶段登记进 [工作表.md](工作表.md) 再开工。

## 0. 一句话

把自由模块从「卡页里的一个盒子 + 画布外的全屏壳」改成「**画布的一等页面 + 页签的全屏状态**」，同时把 AI 编写自由界面的工具链补到能独立迭代、能自检、能复用；沙箱只保留安全必需的边界。

## 1. 现状病灶（HTML 与 3D 是同一个病）

两者都不是「渲染能力不够」，而是「作品没有归属」：

- **HTML**：模块被塞进卡页正文列，套 12px 圆角、520px 高度上限、内部滚动条；头顶是开发态工具条，脚下是卡页剩余的白。它既不是产品的一部分，也不算一个完整作品。
- **3D**：默认页上只有一张封面启动卡（`manifest.fullscreen:true`），真正的场景活在 `createPortal` 的 GameShell 里——窗口级覆盖，不属于画布、不属于页签，自带第二套产品外壳（暂停/存档/截图/导出/分享/退出）。退出即回到盒子，没有「占满画布但仍在页签里」的中间态。
- **共同点**：全屏是一个**画布之外的覆盖层**，不是页签状态。加画布全屏后会出现三层全屏叠加（画布状态 + portal + 浏览器 fullscreen），Esc 归属说不清。
- **AI 侧**：surface 只能整包 JSON 重写，没有单文件写/删/改名/校验；沙箱 console 只进 UI 面板，不回给模型；卡内模块只能读卡图片资源，`.glb`/纹理/音频/JSON 都取不到；用户模块库不支持存界面。于是 AI 即使想做，也做不好、做不快、无法自证。

## 2. 目标

1. **默认走模块**：用户说「做个界面/游戏/3D/图表」，AI 的第一反应是建卡 + 自由模块，而不是写 `.html` 文件。
2. **打开就是作品**：自由模块默认占满画布，无阅读版心、无高度上限、无内滚动；3D 内联即跑，不再先看封面。
3. **全屏是页签的状态**：模块全屏覆盖画布，画布全屏覆盖窗口；一套 Esc 链，不是一个新 portal。
4. **AI 能独立迭代**：按文件读写、有校验、有运行诊断、有截图；不需要整包重写。
5. **自由度拉满**：任意 HTML/CSS/JS（可选 TS 语法糖）、Canvas2D/WebGL2/WebAudio、three.js 及精选 addons；不规定框架。
6. **边界清楚**：禁网、无同源、项目资产只读。需要越界时明确退回文件，并自动挂回卡里。

## 3. 技术栈结论

**展示层就是 HTML/CSS/JS，没有更牛的替代品。** 理由：

- 宿主本身就是浏览器/WebView，HTML 是唯一「AI 直接写、即时运行、可沙箱、可导出单文件」的展示运行时。
- React/Vue/Svelte 等只是组织 JS 的方式，需要构建步骤，增加 AI 负担而不增加自由度；愿意用的 AI 可以在 surface 里自带，宿主不规定。
- Canvas2D/WebGL2/WebAudio 是 HTML 里的能力，不是替代品。3D 用 three.js 是正确默认；Babylon 更重，自研引擎没有必要。
- WASM 可作为可选能力（重计算、移植引擎），但需要 `'wasm-unsafe-eval'` 与工具链，不作为默认。
- Flutter/Skia/原生渲染会失去上述全部优势，不采用。
- TypeScript 作为**可选语法糖**：写 `.ts/.tsx`，宿主转译后运行；只擦类型、不做类型检查（除非后续单独提供 typecheck）。默认仍推荐 JS。

自由层的运行时清单：`HTML + CSS + JS（可选 TS）+ DOM/Canvas2D/WebGL2/WebAudio + three.js（含精选 addons）`。

## 4. 设计原则

- **作品模式与产品模式分开**：内嵌态继承产品令牌；整页/全屏态允许作品自己的画风。
- **状态归页签，不归覆盖层**：全屏、诊断、存档都挂在页签/模块身份上。
- **结构化模块优先，自由模块兜底不了才写文件**；落文件必须能挂回卡里。
- **不为自由层发明第二套外壳**：能用画布现有 chrome 的，不另起 portal。
- **沙箱只放必要的口子**：网络不开、同源不开、写入不开；项目资产只读且按会话围栏。

## 5. 设计决策

### D1 自由模块是页面，不是 widget

- 模块页（`mod:<cardId>:<moduleId>`）对 `html` / `scene` 默认进入**整页态**：复用卡页已有的 bleed 通道（`nv-cardpage-scroll-bleed`），页头让位，模块铺满画布内容区。
- 取消整页态下的 520px 高度上限与 iframe 内滚动；`StageIsland` 走 `fillParent`，高度 100%。
- 卡页/总览仍可保留内嵌预览，但只作为索引缩略，不作为默认打开方式。
- 现有模块页签 key 不变，避免迁移；是否整页由模块 widget 类型决定，后续可提升为模块级 `presentation` 字段。

### D2 全屏是页签状态

- **模块全屏（L2）**：只渲当前活动页签所在叶，压掉其他分栏与页签条；不改布局树，退出即还原。状态挂在 canvas store（按 owner），切页签即退出。
- **画布全屏（L3）**：帧级状态，由 `ui-layout` 提供 `setCanvasFullscreen(on)`；`AppFrame` 用 `data-canvas-fullscreen` 隐藏导航/抽屉/对话列，画布列临时铺满工作层。**只做 CSS/呈现覆盖，不改宽度存档**，退出精确还原。
- **Esc 链**：画布根一个 handler，顺序为 模块全屏 → 画布全屏 → 交给默认（菜单等）。GameShell 自己的 Esc handler 随壳删除。
- 全屏是瞬时视图态，不持久化；切换会话/页签时退出模块全屏，画布全屏按会话退出。

### D3 chrome 预算

- 整页态只留一条**悬浮小条**（返回/面包屑、标题、⋯），滚动或鼠标静止后淡出；AI 修改、运行日志、截图、源码入口全部收进 ⋯。
- 全屏态默认无 chrome，指针移动/聚焦时浮出，Esc 退出提示一次。
- GameShell 的顶栏拆掉；存档/暂停/存档槽/导出/分享变成 manifest 声明的可选 chrome（`manifest.chrome: 'none' | 'game'`），由宿主画成同一条悬浮条，能力仍走桥。
- 不再有第二套产品外壳。

### D4 沙箱边界

- iframe：`sandbox="allow-scripts allow-pointer-lock"`。
- CSP：`media-src data: blob:`（音频/视频）；`img-src data: blob:`、`font-src data: blob:` 保持放行；`connect-src data: blob:` 保持（只够读 blob/glTF）；网络仍全禁。
- 不启用 `allow-same-origin`；localStorage 仍不可用，状态统一走桥。
- 可选（P3）：`'wasm-unsafe-eval'`，只在需要 WASM 时开。
- 项目资产读取必须按会话围栏、只读、拒绝越界路径。

### D5 资产

- 现在卡内模块的 `resolveAsset` 只认卡图片资源；改为：资源 id 按旧逻辑，**其余按项目相对路径**由宿主代取字节，回投 blob URL。
- 宿主侧复用 `/api/noven-frame` 的文件读取与围栏；卡页从画布拿到 sessionId，经 `CardPage → ModuleBox → HtmlModule → StageIsland` 传入。
- 支持 `.glb/.gltf`、纹理、音频、JSON、字体；`manifest.assets` 可显式声明常用资产。
- standalone 导出时，把运行期实际取过的资产业已内联（宿主记录 assetReq 的 blob）。
- 设总量/单文件上限（建议 8MB/4MB，可配），超限给明确错误。

### D6 作者工具

新增 surface 命令族（服务端 `noven-cards`，客户端工具直发），默认按文件操作：

- `surface_read {module_id, path?}`：manifest、entry、文件清单与大小；给 path 时回单文件正文（带 content_ref）。
- `surface_write_file {module_id, path, text, content_ref?}`：新建/覆盖单文件；路径归一化，拒绝 `..` 与绝对路径。
- `surface_delete_file`、`surface_rename_file`。
- `surface_set_manifest`：name/description/cover/fullscreen/chrome。
- `surface_validate`：entry 存在、JSON 可解析、相对 import 可解析、体积上限、可疑路径。
- `surface_init`：把旧原始 HTML 模块包成工程（index.html + manifest），保留兼容。
- 整包 `write_module_text` 保留作批量/逃生通道，但工具描述改为引导逐文件。
- 并发沿用块级 `content_ref`；每次写入回新的 content_ref。

### D7 诊断回路

- 客户端已有 console 环形缓冲；增加去抖上报到 `POST /api/noven-cards/diagnostics`，服务端按 `cardId/moduleId` 存最近 N 条与 ready/error 状态。
- 工具 `surface_diagnostics {root_id, module_id}` 读回最近日志，AI 写完能自证「有没有报错」。
- 页面未打开时无日志，文档要写明；后续可加按需探针（隐藏 iframe 跑 1.5s），列为 P3 可选项。

### D8 复用

- `CustomModuleShape` 增加 `surface`；`save_user_module` / `add_module_custom` 支持存/取整份 surface 工程。
- 模块库新增「我的界面」区；AI 可把一次成果存成模板，下次一键复用。
- 导出：standalone `.html`（已有）+ `.surface.json` 工程包。

### D9 3D 运行时

- `free3d` 预设改 `fullscreen:false`，默认内联即跑；封面/启动卡只作可选 manifest。
- three.js bundle 扩到精选 addons：`GLTFLoader`（已有）、`OrbitControls`、`PointerLockControls`、`RGBELoader`，按需再评估 `DRACOLoader` + decoder（体积/许可/资产路径）。
- `NOVEN_THREE` 仍是唯一入口；文档列出可用导出。未内置的 addon 允许 AI 以文件源码自带，但需要把裸 `three` import 重写到运行时 data URL（`assembleSurface` 支持）。
- 页签不可见/画布收起时暂停 RAF（复用 `gamePaused` 与 visibility 判定），回来恢复。
- 渲染默认：antialias、DPR 上限 2、sRGB、截图需要时 `preserveDrawingBuffer`。

### D10 默认画风与模板

- 每个 surface 注入产品令牌表（`--nv-*`、字阶、间距、圆角、阴影、动效档位）。
- 内嵌态：默认继承令牌，作为「产品内视图」；整页/全屏态：允许自由画风，文档写明这是作品模式。
- 提供 4–6 个在品牌内的起始模板：仪表盘、图鉴/画廊、小游戏、3D 查看器、数据看板、表单工具。
- 不强制；让「跟产品一致」成为最容易的路，而不是唯一的路。

### D11 指令层（默认走模块）

- `LAYOUT_NOTE` 加一条：可看/可交互的东西 → 卡 + 自由界面/自由 3D 模块；只有需要项目资产、外部工具消费或沙箱做不了时才写文件；写文件用 `module_embed_file` 挂回卡。
- 新增手册主题 `surfaces`（`docs/surfaces.md`）：桥 API、模板、限制、示例、诊断；`TOPICS` + docs gate 同步。
- `add_module_preset` / `add_child_module` / `list_module_presets` 描述补 3D 与「优先模块」。
- 工作台手册补一句：画框用于给文件套渲染层；独立互动作品优先自由模块。
- 创作类技能（文游等）按需补「界面部分走自由模块」。

### D12 与画布统一态的接口预留（另立项）

- `CanvasTab` 增加 `presentation: 'inline' | 'page'`；canvas store 增加 `immersive`（模块全屏）与 `setCanvasFullscreen`（帧级）。
- 任何页签（含将来的设置、设定助手、创作库、侧边对话）都能复用同一套整页/全屏状态与 chrome 预算。
- 本计划**不迁移**其他功能进页签；只把接口和状态机留好，避免以后再做一套。

## 6. 阶段

### P0 归属与入口（先让作品像作品）

范围：D11、D1、D3（整页部分）。

- 指令层与手册先落：AI 默认走模块。
- `html` / `scene` 模块页进 bleed 整页；取消 520 上限；开发工具条收进悬浮 ⋯。
- 卡页/总览保留缩略预览。

验收：A1、A9。

### P1 全屏状态机

范围：D2、D3（全屏部分）、D9 的「内联即跑」。

- 模块全屏（只渲焦点叶）+ 画布全屏（帧级隐藏三列）+ 单一 Esc 链。
- 拆 GameShell；存档/暂停/导出/分享变成可选 chrome。
- `free3d` 去掉封面启动，内联运行。

验收：A2、A3、A4。

### P2 作者工具

范围：D6、D7。

- surface 命令族、逐文件写入、校验、诊断上报与读取。
- 旧原始 HTML 的 `surface_init` 迁移。

验收：A5。

### P3 资产与运行时

范围：D4、D5、D9（addons）、D6 的 TS 语法糖。

- 项目资产桥（glb/纹理/音频/JSON）、媒体与 pointer-lock、WASM 可选。
- three addons bundle；未内置 addon 的裸 import 重写。
- `.ts/.tsx` 转译（只擦类型，不做类型检查）。
- 按需诊断探针（可选）。

验收：A4、A6。

### P4 复用与模板

范围：D8、D10。

- surface 存用户模块、模块库「我的界面」、起始模板、令牌表。

验收：A8。

### P5 画布统一态（另立项）

范围：D12 之后的迁移：设置/设定助手/创作库/侧边对话进页签；树与菜单退化为导航。
本计划只交付接口与状态机，不迁移功能。

## 7. 验收场景

- **A1 整页**：从模块库新建自由界面 → 打开即占满画布内容区；无卡页页头、无 520 盒、无 iframe 内滚动。
- **A2 模块全屏**：点全屏 → 页签条与其他分栏消失，作品铺满画布；Esc 回整页；布局树原样。
- **A3 画布全屏**：画布全屏 → 导航/抽屉/对话列让位，窗口只剩画布；Esc 回原布局；宽度存档不变。
- **A4 3D**：自由 3D 打开即跑（无封面）；全屏是同一场景放大；pointer lock 可用；音频可播；项目内 `.glb` 可加载。
- **A5 AI 迭代**：AI 用 `surface_write_file` 改一个文件、`surface_validate` 通过、`surface_diagnostics` 读到 0 错误；坏 entry / 坏路径给出明确错误。
- **A6 导出**：standalone `.html` 仍可离线打开；用到的项目资产已内联；3D 导出 `file://` 无报错。
- **A7 稳定性**：切页签/切会话不丢状态；不可见时 RAF 暂停；控制台 0 pageerror。
- **A8 复用**：把界面存进用户模块库 → 在另一张卡一键实例化。
- **A9 默认路径**：新会话里说「做个 XX 界面」→ AI 建卡 + 自由模块，不写 `.html` 文件。
- **A10 边界**：要求外网/未内置库 → AI 说明边界并走文件退路，文件用 `module_embed_file` 挂回卡里。

## 8. 风险与取舍

- **画布是抽屉里的页签**：画布全屏必须走帧级状态，不能靠局部 CSS 硬改宽度，否则拖拽把手与会话几何会打架。用 `data-canvas-fullscreen` + 呈现覆盖，退出精确还原。
- **三层全屏的历史包袱**：必须先拆 GameShell，再加画布全屏；顺序反了会叠加出三套 Esc。
- **沙箱放口子**：pointer lock、media、WASM 都增加攻击面；保持禁网、无同源、资产只读、路径围栏。
- **资产体积**：glb/纹理/音频可能让工程和导出膨胀；必须有上限与明确报错。
- **逐文件写入的并发**：沿用块级 `content_ref`；整包写入只作逃生通道。
- **TS 的预期管理**：只擦类型、不做检查；文档写清楚，避免 AI 以为有类型保障。
- **跨端格式**：surface 信封保持 `version`，新增字段向后兼容；手机端不在本轮。

## 9. 明确不做

- 不做网络代理/外链加载；需要网络的场景归文件退路。
- 不引入 React/Vue 等框架作为宿主契约；不规定构建步骤。
- 不做 WebGPU 默认路径；不做浏览器级 fullscreen（L4）作为必需项。
- 不迁移设置/设定助手/创作库/侧边对话进页签（P5 另立项）。
- 不碰手机端代码与格式兼容。

## 10. 待拍板

1. 画布全屏用「应用内隐藏三列」还是同时调用浏览器 Fullscreen API？建议先只做应用内，L4 以后可选。
2. 3D 是否永久保留封面启动作为可选 manifest？建议保留为可选，默认关。
3. TS 只转译还是要类型检查？建议 P3 只转译；typecheck 另议。
4. 游戏存档继续 localStorage，还是落项目文件？建议先保持 localStorage + 显式导出，避免把运行时状态混进用户项目。
5. 模块全屏是否允许「只盖画布、保留对话列」？按当前理解：模块全屏盖画布列，画布全屏才盖窗口。
