## 一、产品方向（为什么做）

### 1. 主线：创作好故事　已拍板

- 诺文两件事：**创作好故事**（OC、激发创作欲）+ **文游/Studio**。前者是主线；文游是让用户"玩着写"的创作引擎——把角色放进场景试演、做选择、看后果、沉淀成故事资产——服务于前者，不是独立产品。
- Studio 冻结在作品戏台 v0.3 协议；只保留与写故事直接相关的入口（如角色卡"试演这个角色"）。
- 来源：2026-10 v0.3 收尾期讨论（leader 期望聚焦"创作好故事"）。

### 2. 故事推演四层　已拍板

| 层 | 内容 | 现状 |
|---|---|---|
| ① 命题 | "北伐不是必然失败"类执念/意难平 | 缺 |
| ② 推演 | 因果链、代价、反对者；**分岔卡是基本单位** | 缺 |
| ③ 戏剧 | 选择、爽点、人物动机 | 缺 |
| ④ 文字 | 文风、场景、章节 | 半成品（侧边对话/扩写） |

- 现有能力只覆盖"查得到"（资料/内容树）和"写得出"（扩写）；②③ 缺失是"依然不够"的根因。
- `中华文明史/研究/` 的绍宋拆解（偏差分岔卡、机制、文风、切片、实体、时间线）是"拆解好书写法 → 产品化"的现成范本。
- **待跑样板**：拿"诸葛亮北伐并非必败"手工走一遍四层链路，卡住的地方 = 产品缺口。可再约 3 个新用户做无声观察。

### 3. 二创是主要入口　已拍板

- 分工：**AI 管账，用户拍板**。AI 负责重温原作、梳理人物/时间线/地图/机制、记账（钱粮兵力关系状态）、可视化；用户只做关键分岔决定，不手工整理。
- 画布两层：**底层原作路线（淡）+ 前景"我的改写"（亮）**。归属感来自"原作本来如此，而我改成这样"，不是来自 AI 讲得好。
- 防旁观：AI 持续输出资料/出图/做百科会把用户变成观众；整理与可视化是钩子，必须尽早让用户做出第一个改写决定。

### 4. 新手冷启动　已拍板（方向）

- 用户从**熟悉但记忆模糊**的原作进入，不给空白页。
- 主循环：选作品 → AI 速览（怀旧钩子）→ "哪段最意难平" → 给 2–3 个分岔入口 → 用户第一个决定 → 画布记下"我的版本" → 悬念收尾。
- **选择式追问**：AI 问、用户答（点选），不让用户开口前先想措辞。
- 来源：2026-10 冷启动讨论 + 本轮（输入框聚焦退场 + 五入口）细化。

## 二、交互与手感（怎么做才算"对"）

### 5. 手感是第一公民　已拍板

- 用户原话："细微的手感真的能带来很大的变化。"
- 先例证明投入值得：CardPick 悬浮卡牌（每个 transform 独立分层，hover 永远抢不到 keyframe 的控制权）、时间线边界渐隐（粒子尘尾 → 三角 → 雾化矩形 → 矩形延伸渐隐 + 标尺继续延伸可吸附，多轮真实调试才定）。
- 推论：手感受损的地方视为欠债，不是"能用就行"。

### 6. 规范方法：定模式，不逐屏口述　草案

- 目标：像苹果/腾讯/字节那样——每一步交互有既定处理方式，新页面只描述与既有模式的**差异**，不再每次重新设计。
- 分层：
  1. **原则**：能拍板的少量规则（本文就是原则层）。
  2. **动效词表**：全局统一的时长档位与缓动曲线，新页面从档里挑，不发明新数值。
  3. **状态词表**：每个界面只处于有限状态（空/草稿/聚焦/工作中/待决/出错/未保存）。
  4. **交互模式**：反复出现的交互单元，每个用固定模板写——触发 / 状态与切换（含退出还原）/ 失败 / 键盘 / 动效（引用词表档位）/ 不做什么。
- 代码映射：一个模式 = 一个组件 = 一个状态机；规范写清状态切换，代码里就不会长出补丁式分支。
- 来源：用户"我其实想先设计一个通用规范"（2026-10-13）。

### 7. 新会话与空态

| 条 | 状态 | 内容 |
|---|---|---|
| 空态判定 | 已拍板 | 入口界面显示与否按**"有没有消息"**判定，不按路由——新会话（未创建）与空会话（已创建无消息）同一形态 |
| 会话创建时机 | 草案 | 发第一条消息才真正创建会话（业界惯例，待确认） |
| 聚焦退场 | 已拍板 | 点输入框：卡片等内容**缓缓褪去**，输入框走到正常对话位置；点开别处且未发出消息、草稿为空 → 卡片回来 |
| AI 先开口 | 草案 | 程序直接渲染开场白（不调模型）。**开场白归属于"卡"**——默认是"诺文"卡；换身份 = 换卡，开场白/头像/气泡皮一起换。开场白计入对话历史（OC 卡 `first_mes` 惯例），AI 后续语气接得上 |
| 入口按钮 | 已拍板 | 开场白后跟入口选项；点选项 = 文案进输入框 → 发送（"用户点击按钮就跑到对话框，然后发送"） |
| 五个入口 | 已拍板 | 「历史要是换个走向」/「我有个原创角色」/「一个架空世界」/「我喜欢的作品，想写个同人」/「还没想好，给我点灵感」（文案可再调） |
| "还没想好"落点 | 草案 | 「还没想好」最终应落回前四条路之一，不做第五种独立产品路径——devin 提案，待确认 |
| 气泡+头像 | 草案 | 会话可切气泡+头像视图；它是卡的皮肤，随身份换（阶段 3：会话视图/皮肤/每轮携带） |
| J01 根结构 | 已拍板 | 空项目态最上级只有**一个根卡**——画布默认收起，用户主动开画布才进入"要不要新建一个世界"的流程；不常驻项目头/搜索/新建/素材/功能台全套外壳 |

### 8. 颜色与选中　已拍板

- **绿 = 行动、状态、活物**：可点动作、工作/待决状态点、焦点/拖拽指示。
- **选中/按下/激活 = 灰底 + 深色字/边框**，不用绿。
- 单叶布局不画焦点线（焦点标记只在多分栏有意义）。
- 已执行：页签、模拟器、树、集合、关系图、时间线选中态全部从绿改灰。

### 9. 归属与视角　已拍板（契约 C9）

- **界面绑定会话，内容绑定项目**。"有什么"是项目的，"在看什么"是会话的。
- **页 = 实体化身**，绝对单开；关页 = 停止这件工作，切走 ≠ 关闭。
- 树/分组 = **纯导航索引**；重命名/归档/嵌入等操作挪进页内。
- **位置不固定**：导航/抽屉/画布/会话是四个语义角色，不是固定方位；实现与文档不得按左右写死。

### 10. 页签状态四词　已拍板

| 态 | 表现 |
|---|---|
| 工作中 | 克制的呼吸点（不要加载圈） |
| 待决 | 绿点 |
| 出错 | 红点 |
| 未保存 | 灰点 |

镜像实体态，页不发明状态。回挂页签**先渲旧快照**不白屏（温层原则）。

### 11. 诚实界面　已拍板

- 不许有点了没反应的按钮；未实现 = 置灰 + 注明，或直接如实报错（`starter:template` 回 501，不造假）。
- 错误对象 `message` 给开发者，不给用户看；用户可见文字走 locale。
- 导入没有"失败"态，只有"没挂视图"——如实报告、如实落位。

### 12. 双角色验收　已拍板

- **休闲用户**：默认路径零认知——拖 PNG 进来就是一张卡，永远不该看见源码和 manifest；**撤销永远在手边**。
- **老手**：文件真相永远可达——每个语义视图一步踏进文件层；AI 是第三个用户，不是守门人。

### 13. 工作方式（用户教过、容易忘的）　已拍板

- 讨论 ≠ 授权；分析可以主动，执行必须等明确指令。
- 先理解设计稿/意图再动手——"先理解第一张"。
- 现象优先于猜测，证据优先于直觉；用户的修复方案是待验证假设，不是事实。

## 三、手感现状盘点（2026-10-13 读码记录）

> 事实层：以下为代码现状，不是决定。诊断与方案见 §四。

### 投入过的（手感在线）

- 页面进出场：`nv-page-in` 340ms 对焦式淡入；`nv-ghost` 旧页克隆上浮退出。
- 创作页发送退场：`nv-leaving` 分层（内容先走，输入框延迟 100ms）。
- CardPick：入场 560ms 弹簧 + 80ms 错峰、常驻 5.5s 呼吸浮动、悬停回正 overshoot、命名时双卡让位、退场倒放入场。
- 拖拽提升：`.nv-ed-lift` 克隆 + gap 展开动画。
- 悬停浮起：槽位/模板/feed 卡统一 `translateY(-2~-3px)` + 阴影 .18s。

### 没投入的（手感断裂）

- ~~**删除/改名全部走 `window.confirm` / `window.prompt`，共 21 处**~~（2026-10-14 已全部替换，见 §四）（树 11、画布 3、卡页 2、CardStudio 2、CardEditor 1、地图 2）。原生弹窗冻结全窗口，与旁边精心调的弹簧动画是两个世界。删除后行直接消失，无收缩/淡出，无撤销入口。
- `CreateDialog`（树「＋新建」路径）**零进出场动画**，与 CardPick（创作页/Me 路径）是两种质感——同一动作两条路。
- 上游 `Menu` 弹出瞬时无动画（ui-primitives 无动效属性）；`Modal`/`Tooltip`/`Toast` 有进场动画。
- ~~改名分裂~~（2026-10-14 已统一为 `InlineRename` 行内输入：Enter/失焦提交、Esc 取消、聚焦全选）。
- 动效时长散值 12+ 种（120–560ms），缓动 6+ 种，无共享档位；悬停浮现按钮三种实现（150ms/120ms/无过渡）。
