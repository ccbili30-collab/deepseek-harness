# Noven 工作区外观模型

状态：用户已确认模型，已按本文落地并通过隔离 Web 验收。

## 1. 容器模型

工作区是一个巨大的矩形，也是整套统一外壳。外壳包含导航、项目树、顶栏、边框和其他导航区域；内部嵌两个圆角内容位：画布位与对话位。

```text
工作区大矩形（统一基础风格）
├── 导航区域：导航、项目树与外壳其他部分
├── 圆角画布位：当前文件
└── 圆角对话位：当前会话、对话背景与 AI 头像
```

工作区换基础风格时，整个大矩形及导航区域统一变化，不是只给项目树换一张图。画布与对话是外壳里的内容位，不是独立页面。

## 2. 外观作用域

外观只有两种作用域：

- **工作区默认**：保存在工作区上。新对话自动使用；没有专有覆盖的文件和会话也跟随默认。
- **对象专有**：保存在具体文件或具体会话上，只影响该对象，不修改工作区默认，也不影响其他对象。

解析顺序：Noven 内置默认外观 → 工作区默认 → 文件或会话专有覆盖。移除专有覆盖后恢复工作区默认。

## 3. 可配置内容

### 工作区与导航块

统一基础风格包括导航、项目树、边框、分隔线、容器底色和周围材质。

### 画布位

按文件解析背景。文件背景只改变画布容器显示，不修改文件正文、编辑器、页签和文件状态。

### 对话位

按会话解析背景与 AI 头像。会话外观不进入 Session 消息格式，不改变历史、模型请求、Agent 身份或工具权限。

### AI 头像

头像需要独立的资源引用、默认值、专有覆盖、设置界面和显示机制。用户可以设置，AI 也可以生成并设置。换头像不等于创建 Agent。

### 背景四态与共用图

画布、对话和外壳各自独立支持四种状态：**默认**（内置薄荷加白，文件/会话则跟随上层）、**共用图**、**自定义图**、**关闭（透明）**。关闭背景不等于恢复默认，因为薄荷加白本身也是背景。两栏同时选择共用图、只开画布、只开对话、两栏各自不同图，都是合法状态。

共用图显式引用工作区唯一的 `shared` 图片槽，不是复制后产生隐性联动。各栏跟随同一张图时仍可独立设置焦点、淡化和文字承托；共享槽仍被引用时不可删除，避免孤儿引用。AI 设置图片只等价于把有权作用域设为自定义图，不改变另一栏开关，也不修改共享槽。

### 背景效果

容器只有一层背景：默认是薄荷加白，启用图片就是替换这层背景，关闭就是透明，没有第二个“纸面/蒙版”对象。输入框、预设卡等组件保留自己的底色，但不给侧栏、案头、标题或正文额外加半透明层。

图片支持 `focus`（center/top/bottom/left/right）、`dim`（0–0.6）和 `blur`（0–20px），全部由用户主动选择，默认均为不裁切偏移、不淡化、不模糊。模糊只作用于背景层，不能过滤文字和控件。背景与圆角在同一个容器上裁切，不能用切断主视觉换取圆角。旧文档中的 `surface`/`surfaceOpacity` 只作兼容解析并丢弃，不再恢复任何纸面。

### 嵌景控件与前景

所有嵌在背景上的可点击控件仍走现有组件和唯一的选中态规则：选中只把文字和图标切到 `--nv-select`，不加选中底色；悬停/按压使用统一 hover/active token。皮肤不得给单个按钮写新样式或新选中态。

视觉状态分两层：**背景资源**按工作区/文件/会话管理，**全局视觉状态**只有一份 `view`（light/dark）、`surface`（auto/frosted/clear）、`foreground`（system/light/dark）和 `backgroundVisibility`（0–1）。背景资源可以分栏，但视图、材质和前景默认不分栏；特殊图片才允许作用域覆盖。

`view=dark` 时全应用使用浅色前景和深色玻璃，`view=light` 时使用深色前景和浅色玻璃。没有背景图时，亮暗切换同时更换背景底色、按钮、边框、文字与选中态；有背景图时，图片顶替该作用域底色，亮暗只换图片上的材质、文字和控件，不替换图片。`backgroundVisibility` 只改变玻璃岛的透明度/模糊，不改变布局或点击区域：越接近 1，背景越清楚；越接近 0，面板越适合阅读。起点的案头不再额外套岛，按钮和代码卡仍可有材质。

实现是在作用域根覆盖 token：外壳用 `[data-product-frame]`，对话用 `[data-conversation-root]`，画布用 `.nv-leaf`。控件继续消费 `--nv-*` 和 `--dsw-alias-*`，不按页面重写。磨砂只由实际表面容器承担：输入卡、菜单、独立内容卡和阅读面板各自护化一次；行内文字动作、导航、顶栏和页签不得因语义是按钮就生成背景滤镜矩形。画布叶的宿主保持透明，圆角外显示外壳连续背景。全局视觉 token 通过主题受管覆盖层投到 `body`，让 portal 菜单与浮层跟随同一份视图和前景；作用域根仍可覆盖自己的区域，菜单材质 token 仍由主题包所有。

`view` 同时驱动主题运行时的 `colorScheme`，不再只是外观插件的局部前景提示。外观设置通过 `setTheme` 切换完整调色板、原生表单控件、macOS 按钮和基础背景；视图持久化只归外观文档，主题运行时及普通主题入口不形成第二个写入来源。迟到或外部主题变化会重新服从外观视图，不得把外观文档反向改成另一色。全局视觉状态按 Session 共享一份快照，写入后立即发布；画布叶直接订阅该快照，不得在各自文件背景响应未返回时从默认亮色重新起步。文件背景仍按各自路径解析，切换亮暗不替换图片。

文稿护化挂在完整的 `.nv-ed-main` 容器，覆盖标题与正文所在的整个文稿位；不得分别给 `.nv-ed-head` 和内容高度有限的 `.bn-editor` 再套半高玻璃带。案头没有整层岛，独立瓷砖各自承担一次材质。

分隔线只保留状态或操作含义：选中短绿线、拖拽/分屏 hover、AI 状态和语义化 `hr` 可以存在；品牌头、导航、列宿主和会话 chrome 不画静态分割线。默认 macOS 由 WindowScene 在整个外框只绘制一次原生 vibrancy 与导航渐变，产品侧栏根、品牌行、工作层和列宿主全部透明；非 Darwin 或自定义外壳才接管底色，自定义 shell 图片不叠原生渐变。对话、创作和画布各自是一张完整内容列：工具行与正文同属一列，默认白色从顶栏延伸到底部，四周和列间只留 4px 外框材质缝，列拥有 `.5px + var(--nv-divider) + 12px` 圆角描边与裁切，不添加浮卡投影。案头与文稿只是列的内容状态，不再分别发明 desk/paper 底层；显式透明与图片仍由各分屏叶按文件解析，叶不重复添加窗口级 margin、描边或圆角，画布全屏恢复 `inset: 0` 且去掉列边界。`sideChrome: 'content'` 让展开辅助列持有折叠、主内容列在辅助折叠或全局面板时持有恢复；统一 28px `nv-chrome-icon-button` 与 `data-chrome-command`，所有恢复都参与真实 trailing 排版，框架不再绝对定位或生成第二条轨道。创作不显示 Session 历史，恢复命令返回进入创作前的真实 Session 并展开辅助内容，不新建 Session、不切换主体；空白 Hero 同时受 `hideChrome` 与真实 Canvas claim 约束。折叠品牌轨在 Darwin 下移 52px、原生全屏下移 18px，不能碰红绿灯。输入卡和浮层只使用一种边界表达，不叠加内描边与外部投影。

### 透明背景
透明就是关闭当前容器的背景，与恢复内置默认不同。画布、对话、内联块和其他容器都必须允许透明背景。透明容器显示下层场景，真实文字和控件仍由 Noven 渲染。模块内部可以保留自己的背景，但外层不能强制增加不透明色块。

## 4. AI 权限

AI 只有两类外观写入能力：

1. **换画布外观**：设置背景，并选择工作区默认或文件专有。
2. **换对话外观**：设置背景与头像，并选择工作区默认或会话专有。

AI 可以生成背景和头像资产，但不能借外观设置修改文件正文、消息内容、Agent 配置、导航结构或其他应用设置，也不能创造分页、多 Agent 等不存在的功能。

## 5. 实现约束

- 默认外观与首页保持现状，功能上线不强制换肤。
- 背景是容器的表现层，不是覆盖在按钮和内容上方的图片。
- 真实按钮、分类树、文字、图表和状态仍由 Noven 渲染，不能烘进背景。
- 工作区、文件和会话的配置必须隔离，不能串用。
- 换肤不重建画布或会话，不改变滚动位置和编辑状态，不修改 Session 格式。
- 素材适配现有组件；不为配合皮肤另造布局、角色、按钮或交互。
- 透明背景、细滚动条、文字安全区和视觉居中属于默认验收项，不是可选修饰。
- 每次应用前都要在真实组件和真实数据上进行视觉验收，检查宽窄屏、Agent 与手作、主画布与侧边画布、长文本、空状态、滚动和选中状态。

## 6. 验收底线

- 所有文字位于纸面或面板的安全区内，不被背景遮挡。
- 所有按钮都来自 Noven DOM，背景不包含伪按钮、文字或假控件。
- 工作区默认、文件专有和会话专有分别生效，移除覆盖后正确恢复默认。
- 背景和头像可以独立替换，不改变文件内容、会话内容和 Agent 权限。
- 换肤前后布局尺寸、滚动位置和真实交互保持一致。

## 7. 落地记录

- **持久化**：每个项目一份 `<NOVEN_HOME>/ledger/<project>/appearance.json`，只存稀疏覆盖；Session 日志、标题、消息和 Agent 配置不写入外观。可选 `presets` 在同一份项目外观文档保存命名预设，每项包含全局视觉状态和工作区背景/头像资源；旧文档缺少该字段时按空预设集解析。它不是 Session 持久化类型，不需要 Session persistence acknowledgement，也不改变 Session format version。
- **解析**：`noven-shell/src/appearance/model.ts` 统一解析逐字段继承：外壳/画布/对话/头像分别从内置默认、工作区、文件或会话取最近一层。`transparent` 是显式关闭，`shared` 在 Host 解析为实际图片及本栏效果，删除覆盖后才继续继承；共享引用缺少共享槽时整份文档拒绝解析。
- **写入面**：`service.ts` 只暴露画布与对话/头像两类 AI 写操作；项目内路径经 `realpath` 围栏、普通文件与 PNG/JPEG/WebP/GIF 魔数检查。用户路由额外允许设置工作区导航背景、共享槽、保存/应用预设和恢复 Noven 默认；应用预设会清除文件与会话覆盖，恢复默认保留共享图资源和预设。共享槽被任一作用域或预设引用时拒绝清除。AI 工具没有外壳、共享槽、预设、重置或效果写入入口。
- **AI 工具**：`set_canvas_appearance` 与 `set_conversation_appearance` 只从执行中的 Session 取身份和 cwd，不接受 Session、Agent 或 root 参数；`expected_revision` 防止陈旧覆盖。用户和 AI 都只改变外观文档。
- **客户端**：`appearance.tsx` 每 5 秒读取一次当前 Session 视图；画布每个叶按自己的文件路径解析，外壳、对话与头像由根 overlay 写入 `body` 上的 CSS 变量。焦点写入 background-position，淡化写入背景图层，模糊由独立背景伪层承担；正文、顶栏、导航和编辑器保持透明，不附加纸面，内容元素不继承模糊。背景和圆角由同一画布叶或对话根裁切。
- **控件 token**：`view/surface/foreground/backgroundVisibility` 在文档根保存并解析为一份全局视觉状态；背景资源仍按作用域覆盖。表面 token 按可见度计算透明度，外壳/对话/画布根共享同一前景，只有显式作用域覆盖才允许例外。选中态继续由全局唯一规则消费 `--nv-select`。
- **设置**：独立「外观」设置页只显示一个当前预览、一个作用域/目标编辑器、亮暗与背景四态选择器和背景可见度；路径、焦点、淡化、模糊、材质、前景与头像收进高级效果。全局外观与会话外观共用同一组件，并沿用通用设置的 14px 标题、12px 说明、16px 行距、发丝分隔线、36px 无描边选择器和无壳文字动作，不另建分段按钮控制面板。所有修改即时串行自动保存，接受响应的 revision 同步供下一请求使用，复合写入在入队时确定顺序；本地写入排队期间不被中间回读重置，作用域切换才立即重建草稿，回读追上已接受 revision 后再同步。预设可命名保存并一键回放；「恢复 Noven 默认」始终可见，清空视觉与对象覆盖但保留共享图和预设。通用设置不再出现竞争的主题入口。光缝 range 保留原生键盘/触摸语义，以 1px 轨道、当前值亮点和两侧短光晕表达，不画圆形滑块。
- **验收**：`apps/web/tests/noven-appearance.e2e.ts` 覆盖工作区默认、文件/会话覆盖、共享同图、只开一栏、各自不同图、透明关闭、效果与圆角、头像上传、即时自动保存、预设保存/回放/恢复默认、光缝滑杆、全局亮暗视图、可见度、Agent/手作、深浅色、600px 窄屏、布局列稳定性与无页面错误；显式断言外壳/正文/顶栏透明、模糊只作用于背景、嵌景按钮无纯白、磨砂滤镜生效、点击框尺寸不变，以及选中色等于 `--nv-select`。`snapshots/web/noven-appearance` 以作者态 V4 keyless 快照记录单预览、作用域编辑器、共享图、全局视图、高级效果和光缝控件；Host/客户端单元测试覆盖解析、全局状态、预设生命周期、共享引用保护、旧 surface 丢弃、原子写、损坏文档不覆盖、路径越界、AI 工具 Session 绑定与权限、CSS 变量清理。
- **未做**：文件改名时没有迁移外观键；因为当前只有精确文件覆盖，改名后旧键不会自动跟随。这是已知限制，不把旧键当成有效文件状态修改。

## 8. 全局视觉状态返工八问（2026-11-01）

1. **任务理解**：背景资源分作用域，视觉状态全局唯一；背景可见度与玻璃浓淡可独立调，所有页面一起切换，不做半覆盖和分栏皮肤。
2. **直接原因**：把 material/foreground 挂到各栏背景，导致外壳、画布、对话分家；案头岛过厚遮背景，接缝露白，内联文字也被套壳。
3. **根本原因**：把皮肤做成页面覆盖层和局部组件样式，没有单一全局视觉状态解析器。
4. **同类范围**：外壳、画布、对话、文稿、卡片、菜单、浮层、代码块及所有可点击控件与选中态。
5. **他处**：`--dsw-alias-bg-layer-*`、浮动按钮、返回底部、媒体选择、壳侧新建/工具/设置都纳入同一映射；案头多余岛和列间白缝一并处理。
6. **宪法核对**：保留全局唯一 `--nv-select` 选中规则、薄荷加白默认、共享槽、四态、严格解析、AI 两域权限、布局与 Session/Agent 不变。
7. **修复风险**：token 自引用、作用域选择器错误、前景与材质错配、可见度侵入布局；用稳定基准、全局视图解析和布局无关的内嵌描边控制。
8. **验收**：外壳/画布/对话按钮无纯白、磨砂滤镜生效、点击框尺寸不变、选中色等于 `--nv-select`、全局亮暗视图和可见度可持久化；Host/client/Web/keyless 快照和构建门禁全部通过。

## 9. 重复护化修复八问

1. **任务理解**：消除画布圆角外的异色底层、导航与顶栏分裂、空对话头部占位、行内文字黑条和菜单重复表面；不删除背景、正文、控件或首页内容。
2. **直接原因**：画布叶外三层宿主仍有旧底色；导航单独磨砂而顶栏透明；空头部保留 10px 上 padding 与 30px 标题行；所有按钮被无差别施加背景滤镜；Web 镜像误用原生 macOS 菜单背板；菜单 caption/tertiary/icon 前景未随视图切换。
3. **根本原因**：把材质当成语义元素的通用属性，而不是实际表面容器的责任；外观覆盖只检查容器变量，没有覆盖 portal 与真实子元素。
4. **同类范围**：外壳顶栏与导航、画布宿主与页签、创作 Hero、活动与空白对话、命令菜单、文稿标题与 BlockNote 编辑器、案头瓷砖全部按同一规则处理。

## 20. 页签对象背景与分屏（2026-11-02）

背景绑定的最小对象是有稳定身份的文件页签，不是整个画布容器，也不是当前 Session。每个画布叶继续从自己的 `activeTab.path` 读取 `files[path].canvas`；同一文件在多个分屏中共享设置，不同文件与不同叶互不影响。页签只保存对象引用，外观账本保存背景，关闭或切换页签不删除对象设置，也不把图片写进 Canvas 或 Session 持久化。

文件页签条提供“页签背景”入口，直接打开绑定该文件的编辑器。弹窗锁定当前文件，不显示全局视图、背景可见度、其他作用域或外观方案；背景、焦点、淡化、模糊、材质和前景仍复用同一序列化保存链。起点、终端、工具页没有文件身份，因此不出现独立入口，继续跟随工作区默认。

外观页是统一管理与工作区默认的入口，页签设置是当前文件例外的入口，对话设置是当前会话例外的入口，三者编辑同一份 `appearance.json`。统一背景 → 工作区画布默认 → 文件页签背景的解析顺序不变，页签选中态仍只使用 `--nv-select`。

## 29. 对象音轨与独立前景（2026-11-04）

音轨复用外观的稀疏对象绑定，但不进入 Session 日志。对话音轨只读取 `sessions[id].track`；画布按 `files[path].track ?? sessions[id].track ?? workspace.canvasTrack` 解析，因此文件可以覆盖 Session 与工作区画布默认，删除文件例外后重新继承。当前模型没有全局音轨或全局音频库，也不把外框背景误当成一个音频播放器。工作区外框、对话、画布背景仍按第 22 节的五层背景规则独立解析。

文件与 Session 另有 `foreground: light | dark | invert`，优先于全局视觉前景；画布文件未指定时继承 Session，再继承全局视觉。固定浅色/深色只覆盖文字与图标 token；反色对实际背景 RGB 做简单取反，不反背景图片，不引入感知亮度或对比度算法。图片背景以一像素采样为本次尝试的近似值，透明背景沿父级寻找实际底色。

唯一 `AudioPlaybackController` 持有应用内唯一的当前音频。标题点击是首次播放的唯一入口，刷新和仅仅打开有音轨的对象不会自动播放；中央对象或焦点叶变化时，已经启动的播放才按新解析结果淡出换轨，用户暂停优先，不会被轮询或切页强行恢复。晚到的 `play()` 结果用 generation 丢弃，分屏不能叠音。项目标题与每个文件页签分别读取自己对象的音轨；有音轨时，鼠标悬停或键盘聚焦把标题换成播放/暂停图标，标题最小宽度只增不减，页签关闭叉始终是独立兄弟按钮。

设置页在工作区、文件和 Session 作用域复用同一音轨编辑器，支持项目音频路径、上传、音量、循环与对象前景。原始覆盖和解析后的继承值分别保存，修改对象前景不会把继承音轨写成显式覆盖。上传只接受 MP3/WAV/Ogg，同时检查扩展名与真实字节，限制 16 MiB；图片仍走独立 8 MiB 通道。清除绑定只删除外观引用，不删除项目文件。外观编辑器和页签弹窗增加视口最大高度与内部滚动，音量/循环合并为一行，避免新增控件把关闭按钮推出屏幕。

1. **任务理解**：交付用户已确认 Demo 的真实产品模型：默认与对象音轨、对象文字亮暗/反色、标题播放键和中央唯一播放，不修改首页、背景模型或页签关闭能力。
2. **直接原因**：旧外观文档只保存背景与全局前景，没有音轨字段、对象前景、音频资产通道或中央播放所有者，标题也只是普通激活按钮。
3. **根本原因**：背景资源解析与瞬时媒体控制未被拆成持久绑定和运行时所有权两层；若由每个标题各自创建音频，分屏必然叠音并互相抢状态。

## 30. 模型音轨编排工具（2026-11-04）

模型现在拥有一对音轨编排工具，仍由执行中的 Session 授权，不新增 Session、Agent、项目根或任意文件参数：

- `list_soundtracks`：读取工作区画布默认、当前 Session 的原始音轨与前景，可选读取一个现有文件的覆盖；同时返回每层解析后的画布/对话音轨与前景、外观 revision，以及项目内可绑定音频。音频列表排除 `.git` 和 `node_modules`，只包含 1 字节到 16 MiB、扩展名与字节头都受支持的 MP3/WAV/Ogg，最多返回 200 个并明确标记截断总数。
- `set_soundtrack`：设置或清除 `workspace` 画布默认、当前 `session`、一个现有 `file` 的音轨；文件和 Session 可选择 `light`、`dark`、`invert` 前景。`track_kind=default` 只删除该层引用并恢复继承，不删除音频文件。`audio_path` 必须指向工作区内真实音频；`volume` 为 0–1，`loop` 为布尔值。`expected_revision` 继续提供乐观并发保护。

工具直接复用用户面的 `setTrackAppearance()`、`projectPath()` 与外观文档，不建立第二套持久化或另一条上传通道。它们只改变外观绑定，不会开始播放、暂停当前音乐、上传或生成音频、创建 Session，也不能写其他 Session。返回对象同时包含原始覆盖和解析结果，模型无需猜测“清除文件音轨后继承到 Session 还是工作区”。

1. **任务理解**：让模型能自己读取、选择并绑定已有项目音轨，同时设置对象文字前景；不授予音频生成、上传、播放控制或跨 Session 写权限。
2. **直接原因**：音轨模型和用户设置已经落地，但模型侧四个外观工具仍只有背景与头像，`setTrackAppearance()` 没有暴露给 Agent。
3. **根本原因**：外观服务已按统一领域实现，模型权限面却仍停留在旧的两域声明；模型也没有只读入口获知继承值、revision 和可用音频。
4. **同类范围**：工作区画布默认、当前 Session、任一现有文件、清除与继承、音量、循环、浅/深/反色、陈旧 revision、路径越界、伪装音频和其他 Session 隔离全部覆盖，没有只给当前页签做特例。
5. **他处**：背景与头像工具保持原权限；用户 HTTP 写面、上传通道、播放器、设置 UI、分屏解析和项目文件内容不变。音频列表只读，不把目录扫描变成新的写入能力。
6. **宪法核对**：工具身份只来自执行 Session，文件与音频继续经过 `realpath` 工程围栏和真实字节检查；文档仍是稀疏外观账本，未改 Agent、`agent-loop`、Session 格式或真实数据。
7. **修复风险**：模型可能把“移除”误解成删除文件，因此结果返回继承值和清除语义；列表可能过长，因此返回上限与总数；引用音频与上传现在共用 16 MiB 上限，避免模型绑定超大文件绕过上传限制。

## 31. 视图切换覆盖 macOS 外框修复（2026-11-04）

1. **任务理解**：浅色、深色、前景和背景可见度只改变内容与文字；没有自定义外壳背景时，外框必须继续显示 macOS 原生 vibrancy 和导航渐变，不能变成白色实底。
2. **直接原因**：非默认视觉状态会添加 `data-noven-shell-foreground`，旧 CSS 把这个属性当成外壳表面覆盖，使用 `--noven-shell-background-color` 回退到侧栏白色，并清除原生渐变；浅色分支没有写入外壳背景色，所以深色切浅色后白色最明显。
3. **根本原因**：前景 token 与外壳背景所有权混在同一个属性上；`isDefaultVisual()` 又把背景可见度纳入“是否需要前景”，导致调整可见度也会触发非原生外框。
4. **同类范围**：浅色/深色、任意可见度、显式前景、无外壳背景、默认/透明/图片自定义外壳、Agent/手作和分屏全部覆盖。
5. **他处**：文字前景仍由 `data-noven-shell-foreground` 驱动；非 Darwin 画面仍使用实色表面；自定义外壳图片仍由 `data-noven-shell-appearance` 接管外框。播放、音轨、内容列和主题 scheme 不变。
6. **宪法核对**：macOS 原生材质重新成为无自定义外壳背景时的唯一外框所有者；浅色/深色不伪造外壳背景，背景和文字的既有作用域、选中态、布局和真实控件不变。
7. **修复风险**：不能简单删除前景属性，否则显式前景和无背景的深色文字会失效；CSS 只把表面覆盖收窄到自定义外壳，前景继续存在，原生材质选择器只排除真实外壳背景。
8. **验收**：静态规则检查覆盖“前景不得选择外壳填充”和“无背景时原生材质优先”；真实 Appearance E2E 6/6 新增 dark→light、可见度 100%、无外壳背景的外框断言，确认背景色不是白色且原生渐变仍存在；聚焦 lint 通过。`0.1.7-rc.2.20261104.5` packaged smoke、DMG/ZIP 完整性、包内规则检查和正式 App 截图复核通过；旧 `.4` 已备份并替换，正式窗口恢复 macOS 原生半透明材质，运行 profile 指向新包。
