# 三视图原型校准记录

> 自 2026-10-28 起，逐条记录用户在交互原型上指出的不合理设计。后续正式实现与验收必须遵守这些校准；编号连续追加，不把用户的修正稀释成可选偏好。与旧理解冲突时，以最新校准为准，并同步更新相关设计锚点。

## 1. 整体左右关系颠倒

- 用户反馈：“你左右完全反了，给我换过来。”
- 固定顺序：Agent 为「左侧导航与会话列表｜中间当前对话｜右侧可折叠画布」；手作为「左侧收缩图标工具栏与临时目录｜中间项目画布｜右侧可折叠对话栏」。
- 首页沿用同一外壳方向，不另起一套左右关系。
- 临时目录位于左侧导航内侧；手作历史仍在对话区域临时浮层，不改变这条区域顺序。
- 此前把导航放在最右、把手作对话放在最左的理解作废。换方向时不能只换某一个视图，也不能交换对话与画布各自的职责。
- 状态：已于 2026-10-28 在交互原型中改正；生产前端尚未因此条记录而修改。

## 2. Agent 工作区必须是项目套会话

- Agent 下方工作区按「项目 → 该项目中的会话」组织，不能只给当前项目平铺一串会话，也不能把项目选择与会话导航拆成两套互不相干的列表。
- 项目是可展开的会话分组，也是工作区的层级来源；切换其他项目中的会话时，同时明确切换项目与当前会话。
- 现有项目切换设计保留。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 3. Agent 固定为导航、对话、画布三栏

- Agent 的区域顺序为「项目会话导航｜当前对话｜画布」，对话是主视图，画布是辅助工作区。
- 画布可以展开或收起，但不能借视图切换把当前对话替换掉；当前原型用「对话／分屏／画布」三选一表达这层关系，不符合三栏布局。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 4. Agent 必须有专用画布开关

- 恢复用户示意的侧栏式画布开关按钮；新建会话的笔按钮不能代替画布开关，也不能成为顶栏唯一动作。
- 画布开关只控制画布的展开与收起，不切换项目、会话或视图，不影响画布中已经打开的对象。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 5. Agent 的会话导航只能出现一处

- Agent 已在左侧导航中提供项目会话树，对话顶栏不再重复出现时钟历史入口。
- 手作没有常驻会话列表，因此保留对话区域中的临时历史浮层；这与 Agent 的重复入口是两个场景，不能一刀切删除。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 6. 手作的内容目录只能出现一处

- 同类内容或入口同时只出现一次。当前原型把内容目录入口同时放在侧边栏与画布顶栏，下一版收敛到侧边栏一处，画布顶栏不再复制。
- 目录入口去重仍然有效；“选中对象后退出”的旧规则由第 13 条取代，目录现在的开合见第 12、13 条。
- 状态：已于 2026-10-28 按「侧边栏唯一目录入口」在交互原型中落实并验证，待用户确认这一理解；生产前端未修改。

## 7. 侧栏保留展开能力，但手作宽度应更小

- 手作不能完全取消侧栏展开能力；需要浏览目录或使用侧栏功能时仍可打开。
- 手作侧栏不再显示长会话标题，默认展开宽度应小于 Agent 的项目会话导航，避免按 Agent 的宽度占住画布。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 8. 相邻工作区域必须统一支持拖拽调宽

- Agent 的「导航 ↔ 对话」与「对话 ↔ 画布」分隔都必须可拖拽；手作的「导航或目录 ↔ 画布」与「画布 ↔ 对话」也遵循同一行为。
- 拖拽只改变区域宽度，不改变区域职责、排列顺序、当前项目、当前会话或视图，也不能清空页签、草稿和编辑状态。
- 这属于整类区域分隔的共同能力，不能只给截图中的两条缝补特例。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 9. 可收起区域必须保留自己的打开入口

- 用户反馈：“既然这里提供一个收起按钮，那么也应该同样提供一个打开按钮。”Agent 画布也必须能够直接关闭、收起并恢复。
- 任何可收起的辅助区域，折叠后都必须在原区域边缘保留可见的打开入口；不能让区域整体消失后只能去其他菜单寻找恢复动作。
- 手作对话与 Agent 画布采用同一组行为：区域工具栏收起 → 原位置的小按钮打开（第 17 条进一步明确不做整条大折叠栏）。折叠只隐藏内容，不删除会话、对象、页签、草稿或已调整宽度。
- Agent 画布开关归入画布自身及其折叠轨，不再只放在全局顶栏；新建会话的笔按钮仍只负责新建会话。
- 手作主导航已有展开／收起对称入口，临时目录也能从侧栏重新打开；手作中央项目画布是永久主工作区，不套用辅助区域的折叠规则。
- 状态：已于 2026-10-28 在交互原型中落实，并通过 Agent 画布与手作对话的收起、恢复及宽度保留验证，待用户验收；生产前端未修改。

## 10. 同一开合按钮只能沿一个轴移动

- 收起与打开应当是同一个持续存在的控制，不是两个位置不同的按钮轮换；图标和可访问名称可以随状态变化，控制的归属不能变化。
- 水平收起时，按钮只能随区域边缘水平移动，纵向位置保持不变；垂直收起时，按钮只能垂直移动，横向位置保持不变。不能在两个轴上同时跳到另一处。
- 这条不是把按钮锁死在固定坐标，而是要求开合运动保持同一轴线和同一区域锚点。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 11. 侧边通道与工具栏对话按钮不能职责重复

- 当前原型同时提供边缘对话开合按钮与工具栏对话按钮，两者都控制同一对话区域的显隐，形成重复和冲突。
- 两个入口只有在职责不同的情况下才可以共存：区域开关负责显隐，工具按钮负责选择内容；不能都以“对话”为名执行同一种切换。
- 工具栏不再保留同名的对话显隐开关；区域边缘按钮负责显隐，工具按钮负责选择工具。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 12. 内容目录也需要对称开合

- 内容目录与对话、画布等辅助区域一样，需要明确的打开与收起行为，不能只考虑打开后的状态。
- 目录的区域开关、折叠通道和工具入口同样必须区分职责，并遵守第 9 条的可恢复与第 10 条的单轴移动规则。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 13. 目录选中对象后不再自动收起

- 用户反馈：目录已经打开且画布是主视图，点击对象只负责打开或激活对应画布页签，不应立即替用户收起目录；需要收起时由用户主动点击目录开关。
- 本条取代此前“目录是选中后退出的临时对象选择器”规则。目录可以持续用于浏览和切换对象，只有用户明确关闭、切换确有冲突的窄屏面板或其他明确流程需要时才退出。
- 历史浮层是否选中后关闭不因本条自动改变；目录与历史不能继续共用同一种临时选择器假设。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 14. Agent 对话顶栏不能横跨画布

- Agent 的会话标题与对话工具只属于对话列，顶栏宽度应随对话列变化；画布打开后，对话顶栏不能同时占住画布顶部。
- 画布使用自己的对象页签与工具栏。全局窗口顶栏与对话区域顶栏是不同层级，不能混为一个通栏。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 15. Agent 打开画布后仍须能打开工作目录与功能列表

- 当前原型在 Agent 画布中缺少明确的工作目录与功能列表入口，不能因画布打开而丢失这些能力。
- 工作目录、功能列表、对象动作与画布开合是不同控制，不能全部塞进对话顶栏，也不能只保留画布分屏与收起按钮。
- 入口的具体归属与排列需结合第 11–14 条一起确定，保证 Agent 与手作共享能力而不复制同一动作。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 16. 工作目录与功能列表都属于画布挂窗

- 用户反馈：功能列表的下拉与外点关闭合理，旁边的工作目录不应被遗忘；工作目录属于画布，不应以侧栏形式与对话抢位置。
- 目录与功能列表的挂窗只用于适合的场景；第 25 条进一步明确目录宽屏必须归导航，只有窄屏才从对应入口挂窗。目录不再以顶部常驻面板挤占对话或画布。
- 挂窗支持点击外部、Escape 与再次点击入口关闭。继续遵守第 13 条：点击目录中的对象只打开或激活画布页签，不因此自动关闭目录。
- 本条取代此前把目录做成左侧辅助面板和折叠通道的方案；第 12 条的对称开合与第 10 条的单轴控制仍适用于挂窗入口。
- 状态：已于 2026-10-28 在交互原型中落实，并验证挂窗位于画布范围内、选择对象保持打开、外点关闭及对话不受影响，待用户验收；生产前端未修改。

## 17. 收起只保留小按钮，不生成大折叠栏

- 用户反馈：Agent 收起后单独出现一条大按钮区域是不必要的。
- Agent 画布与手作对话收起时都只保留原来的小图标开关，不再显示整条折叠栏或新增大块占位按钮。
- 小按钮继续保持同一实例与第 10 条的位置约束，收起只隐藏内容，不损失页签、会话、宽度或恢复能力。
- 状态：已于 2026-10-28 在交互原型中落实，并验证按钮开合前后均为 30×30 且坐标不变、折叠栏数量为 0，待用户验收；生产前端未修改。

## 18. 设置使用全局浮窗

- 用户反馈：设置不应在侧边打开页签，而应直接在整个界面上放浮窗。
- 设置从任何入口打开时都覆盖应用内部区域，以居中浮窗呈现；不再生成侧边面板、画布页签或对话内容。
- 浮窗支持关闭按钮、点击背板与 Escape 关闭，并在关闭后把焦点还给设置入口。
- 状态：已于 2026-10-28 在交互原型中落实，并验证浮窗覆盖应用内部、无侧边面板及 Escape 关闭，待用户验收；生产前端未修改。

## 19. 相邻工具按钮必须共享对齐关系

- 用户指出历史、区域开关等相邻图标发生错位。相邻按钮必须处于同一工具行，共享尺寸、间距与垂直中心线，不能用各自独立的偏移量拼凑位置。
- 第 10 条的单轴移动与第 17 条的小按钮不能成为错位的理由；开合前后都应落在同一套工具栏几何中。
- 状态：已由第 28 条解决，按钮现在同父级、同行、同高并真正平行，待用户验收；生产前端未修改。

## 20. Agent 的工作目录入口归导航栏

- 用户反馈：Agent 以会话为主视图时，工作目录应位于导航栏，而不是被移到画布工具区。
- 第 16 条不能把“目录属于画布”一刀切到所有视图。Agent 的目录是导航能力，入口应留在项目会话导航体系内；打开画布不能把目录职责搬走。
- 手作的目录与画布关系按对应视图继续校准，但同一目录数据、搜索和对象行为不能变成两套。
- 状态：第 39 条已取代 Agent 目录归导航的理解，Agent 目录归画布及其折叠入口；生产前端未修改。

## 21. 首页不重复提供新建会话按钮

- 首页的真实输入框已经承担开始对话的任务，全局顶栏的新建会话笔按钮在首页属于重复入口，应隐藏。
- 新建会话统一由首页承担，其他视图也不保留重复按钮（第 26 条）。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 22. 首页保留下方的手作与导入首步动作

- 首页不使用 Agent／手作分段切换器。默认开始方式仍是 Agent 对话，输入框下方并列提供“手作”和“导入”两个首步动作。
- 已核对现有 `pages/Create.tsx`：旧设计就是 composer 下方的 `nv-create-paths`，包含 handcraft 与 import 两条路径，应保留而不是另造模式切换。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 23. 搜索必须内置在工作目录树中

- 搜索不能在旁边再生出一份对象列表或第二棵树。工作目录本身就是搜索与浏览内容的同一处结构。
- 搜索入口应打开工作目录并聚焦其筛选输入，过滤现有树；不能再用独立搜索面板复制目录内容与选择行为。
- Agent 与手作使用同一个目录搜索模型，区别只在目录入口和呈现位置。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 24. 终端等持续工作工具以画布页签展开

- 终端应打开或激活画布中的工具页签，与文档等对象共享页签、分屏、关闭和真实状态，不再生成侧边工具面板。
- 对“所有工具”按职责统一：需要持续工作的工具页遵守页签模型；目录与搜索属于导航，功能列表属于菜单，设置属于全局浮窗，对话属于协作面板，不能为追求一律而重新混成同一种界面。
- 状态：已于 2026-10-28 在交互原型中落实并通过相应交互验证，待用户验收；生产前端未修改。

## 25. 宽屏目录放导航，只有窄屏才使用挂窗

- 用户反馈：手作以画布为主视图时，工作目录不应仍从顶部弹出；顶部收起形态只应在压缩情况下存在，宽屏应直接放入导航。
- 宽屏下，手作的工作目录作为左侧导航面板展开；Agent 的工作目录位于画布，并以画布挂窗呈现，不进入会话导航。两者都内置同一个搜索框与目录树，手作对话不被挤走。
- 手作只有窄屏才切换为顶部挂窗；Agent 的目录始终归画布，折叠画布时不显示目录入口。宽窄切换只改变呈现方式，必须保留目录开关状态、当前对象与搜索结构，不能先以“外点关闭”清空目录再换形态。
- 目录选中对象后仍不自动关闭；宽屏外点不收目录，窄屏挂窗支持外点与 Escape，手动关闭均由用户决定。
- 状态：已于 2026-10-28 在交互原型中落实，并验证宽屏导航、窄屏挂窗、单一搜索框、选对象保持及宽窄往返状态保留，待用户验收；生产前端未修改。

## 26. 新建会话统一由首页承担

- 用户反馈：既然首页已经承担开始对话，其他位置不应继续保留新建会话按钮。
- 新建会话只从首页开始。移除全局顶栏、工作区标题和历史浮层中的所有新建会话快捷按钮，不再按“仅首页隐藏”处理。
- 既有会话仍可通过项目会话树与历史打开；首页的手作与导入首步动作保持不变。
- 状态：已于 2026-10-28 在交互原型中落实，并验证所有 `new-session` 动作与按钮数量为 0，待用户验收；生产前端未修改。

## 27. 三层 chrome 不能重复表达同一层级
