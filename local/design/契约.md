# 契约

> 前端、后端、手机端之间的约定。**先有契约，再有实现**：实现者不得自己发明接口；发现契约不够用，先改本文并在 [迁移任务书](迁移任务书.md) §13 留痕。
> 每节标明状态：**已实现**（代码为准，本文是说明）/ **草案**（待对应阶段开工时定稿）/ **预留**（只占名字）。

## 总则

- 所有卡的修改走 **EditorCommand**（`plugins-noven/noven-cards/src/editor.ts`）。界面和 AI 共用同一套命令。
- 新的用户数据一律带 `version`，向后兼容读旧版本。
- 对外的编号都是不透明字符串（卡编号、模块编号、块编号、条目编号）。
- 写入落在**最新内容**上，不依赖读取时的版本号（抽屉原则）。
- 用户可见文字走 locale；错误对象里的 `message` 给开发者，不直接给用户看。

## C1 对象登记（客户端）　状态：草案（P1 定稿）

**目的**：画布里每种可编辑的东西（文档、时间线、集合、HTML……）登记一次，内容树、模块库、总览、画布都从这里读。加新类型 = 加一条登记，不改外壳。

**宿主**：新的客户端服务 `novenObjects`。由哪个插件提供在 P1 开工时定（建议新建 `noven-objects`；也可先放在 `noven-shell`），**接口不变**。

```ts
/** 一个对象的地址：卡内模块，或一个项目文件。 */
export type ObjectAddress =
  | { readonly kind: 'module'; readonly cardId: string; readonly targetId: string; readonly moduleId: string }
  | { readonly kind: 'file'; readonly path: string }

/** 编辑器/查看器拿到的数据和命令通道。组件不得自己 fetch。 */
export interface ObjectHost {
  /** 当前对象解码后的数据；变化时重新渲染。 */
  readonly data: TData
  readonly address: ObjectAddress
  /** 发一条命令（落在最新内容上，返回后数据自动刷新）。 */
  apply(command: EditorCommand): Promise<void>
  /** 当前选中的东西，Editor 负责设置，对话栏据此显示「已选中」。 */
  readonly selection: ObjectSelection | null
  setSelection(next: ObjectSelection | null): void
  /** 挂起的 AI 提案里涉及本对象的部分（见 C5）；没有则为空。 */
  readonly proposals: readonly ProposalChange[]
  /** 只读场景（玩家预览、总览缩略块）。 */
  readonly readOnly: boolean
  /** locale 取词函数。 */
  readonly t: (key: string, params?: Record<string, string | number>) => string
}

export interface NovenObjectType<TData> {
  /** 稳定类型 id：卡内模块用 `widget.type` 对应；纯文字模块的 id 是 'document'。 */
  readonly id: string
  /** locale 键，不要写字面量。 */
  readonly labelKey: string
  readonly icon: string
  /** 新建时要执行的命令（模块库点选后调用）。 */
  create(init: { name: string; parentId: string | null }): readonly EditorCommand[]
  /** 解码/编码载荷，规则见 C3。 */
  readonly codec: ObjectCodec<TData>
  /** 画布里的完整编辑器。 */
  readonly Editor: ComponentType<{ host: ObjectHost }>
  /** 只读查看器：玩家视角、手机预览将来只用它，所以必须能独立渲染。 */
  readonly Viewer: ComponentType<{ host: ObjectHost }>
  /** 世界总览里的缩略块。 */
  readonly Tile: ComponentType<{ host: ObjectHost }>
  /** 本类型的 AI 工具名，用于把提案标注为「AI 改的」。 */
  readonly aiTools?: readonly string[]
}

export interface ObjectCodec<TData> {
  decode(raw: string | undefined): TData            // 宽松：旧版本、缺字段都要能读
  encode(data: TData): string                       // 严格：永远写出最新版本
  readonly empty: TData
}

export interface ObjectSelection {
  /** 选中物类型，如 'timeline.event'，见 C4。 */
  readonly type: string
  readonly label: string
  readonly address: ObjectAddress
  readonly itemId?: string
}
```

**规则**

1. 编辑器只**读 `host.data`、调 `host.apply`**，不碰网络、不碰文件、不碰全局状态。
2. `Viewer` 不依赖 `Editor` 的任何东西。
3. 登记表按 `id` 查；找不到类型时画布显示「这类内容暂时只能查看源码」，**不得白屏、不得抛错**。
4. 内置登记：`document`（纯文字模块）、`html`（既有 `widget.type='html'`，沙箱 iframe）。P2 加 `timeline`、`collection`。

## C2 卡 API（HTTP + 工具）　状态：已实现（含 P0.1）+ 草案（后续操作）

**路由**：`/api/noven-cards`（`plugins-noven/noven-cards/src/routes.ts`）。会话通过 `?session=` 或请求里的会话参数定位项目。

### 已实现

`GET`（无 `card`）→ `{cards: [...]}` 列表；`GET ?card=<id>` → 可编辑状态：

```
{ cardId, dir, revision, version, hasDraft, draftSource, canUndo, canRedo,
  document: { id, kind, name, modules:[{id,name,blocks:[{kind:'text',id,text,ref}|{kind:'image',id,resourceId,caption?}],
                                          children, characterIds, layout, widget?}], characters:[…], … },
  resources:[…], coverResourceId,
  hasProposal, proposal: { pending, baseRevision, changes } | null, aiTrust }
```

`?preview=1` 返回叠加挂起提案的文档（幽灵态渲染用）；省略则返回 head（或草稿）。

注意：文字块带 **`ref`**（内容引用）。写同一个块时把它原样作为 `expectedContent` 传回，块在此期间被别人改过就返回冲突；不传就是「后写者胜」（历史里仍可撤销）。

`POST`，`op` 取值：

| op | 说明 |
|---|---|
| `create` | `{kind:'WORLD'\|'CHARACTER', name}` 建空卡 |
| `apply` | `{cardId, targetId?, command}`，**直接套到最新内容并提交**，返回 `{ok, revision, version}`。`version` 字段已**不再需要**（传了被忽略） |
| `undo` / `redo` | 追加式，历史快照只增不改 |
| `commit` | `{cardId, version}` 提交一份待确认的草稿（导入确认用）；**这里版本仍是严格的** |
| `discard` | 丢弃草稿 |
| `import` | 交换包或外来角色卡文件，落成待确认草稿后提交 |
| `move` / `delete` / `export` | 搬家 / 软删除 / 导出 `.novex.zip` |

**错误**

| 状态 | 体 | 含义 |
|---|---|---|
| 409 | `{error:'conflict', scope:'block', moduleId, blockId, message}` | 同一个文字块在你读取之后被改过（只拦这一个块） |
| 409 | `{error:'conflict', version}` | 仅 `commit` 传了过期版本 |
| 400 | 纯文本 | 命令不合法 |
| 500 | 纯文本 | 其他失败 |

客户端 `card-api.ts` 把任何 409 都抛成 `CardConflict`；界面应只刷新**冲突的那一块**，不要整卡刷新。

## C3 数据格式 v2　状态：已实现（P0.4 编解码 + 编辑器命令；`formats.ts`）

> **2026-10-06 更新（D8）**：手机端等桌面全部做完再兼容。下面这节的 Android 约束是**将来适配的参考，不是当前的硬约束**；桌面端为了体验可以直接改格式（包括 `nodes` / `items` 内部），只要升 `version`、桌面端仍能读旧版本、并同步改写本节。顶层 `noven` 键的设计仍然推荐保留，因为它让将来适配的代价最小。

### 手机端现状（已核实，`ContentModuleDocument.kt`）

- 解码用宽松读取（`optString` / `optJSONArray`）：**多出来的字段不报错，只是忽略**。
- `edit()` 会保留**载荷顶层**的未知键（只移除它自己认识的 `kind/version/text/caption/description/nodes/items/originalType/presentation/contentJson`，再合并重新编码的部分）。
- 但重新编码时，`nodes` 只写 `time/title/description`，`items` 只写 `id/name/summary/description/visualKey`：**条目内部的未知字段会丢**。
- 未识别的 `kind` 会作为 `Unsupported` 原样保留。

### 由此得出的规则

1. 新数据放在载荷**顶层的 `noven` 键**下，不放进 `nodes[]` / `items[]` 内部。
2. 手机端能读的**兼容投影**（`nodes` / `items`）必须由桌面端始终保持同步写出。
3. 桌面端读取时：`noven` 存在则以它为准，再用投影对账（见下）；不存在（v1 旧数据）就从投影生成，位置标为「未放置」。
4. `version` 升到 2；桌面端读 1 和 2，只写 2。

### 时间线 v2

```json
{
  "version": 2,
  "kind": "timeline",
  "nodes": [ { "time": "神历 342 年", "title": "迁都", "description": "……" } ],
  "noven": {
    "calendar": { "name": "神历", "unit": "年", "epoch": 0, "step": 1, "format": "神历 {n} 年" },
    "eras": [ { "id": "era-1", "name": "联盟纪", "from": 120, "to": 240, "color": "blue" } ],
    "events": [
      { "id": "ev-1", "at": 342, "until": null, "title": "迁都", "description": "……", "characters": ["<角色卡编号>"] }
    ]
  }
}
```

- `at` / `until`：有限数值，单位由 `calendar.unit` 说明；`null` = 未放置在轴上。`from <= to`。
- **刻度精度用户可调**（已定，2026-10-06）：`at`/`until`/`from`/`to` 一律存数字，不分「年月日」字段；精度由 `calendar` 表达——`step` 是拖动吸附步长（如 `1` 年、`0.1` 年、`30` 天），`epoch`/`format`/`unit` 决定显示文字。调精度只改 `calendar`，不迁移事件数据；用户和 AI 都可通过 `timeline_set_calendar` 改。
- `color` 取调色板 id：`purple | blue | pink | green | amber | gray`。
- **`nodes` 由桌面端按 `events` 的 `at` 升序（未放置的排最后）重新生成**，`time` 取 `calendar.format` 渲染的文字。
- **对账**（手机端编辑过 `nodes` 之后）：按顺序用 `title` 把 `nodes` 匹配回 `events`；匹配不上的 `nodes` 当作新事件（`at: null`）；`events` 里找不到对应 `nodes` 的视为手机端删除。有单元测试覆盖，夹具要**模拟 Android 的编辑**（丢掉条目内部额外字段）。

### 集合 v2

```json
{
  "version": 2,
  "kind": "collection",
  "items": [ { "id": "it-1", "name": "沼泽部族", "summary": "", "description": "", "visualKey": null } ],
  "noven": {
    "fields": [
      { "id": "f-leader", "name": "首领", "type": "text" },
      { "id": "f-base",   "name": "据点", "type": "place" },
      { "id": "f-cover",  "name": "封面", "type": "image" }
    ],
    "values": { "it-1": { "f-leader": "……", "f-cover": { "resourceId": "<卡的资源编号>" } } },
    "view": "cards"
  }
}
```

- 字段类型：`text | longtext | date | person | image | place | link`。`person` 的值是角色编号；`image` 的值是 `{resourceId}`，图片本体走卡的 `resources`（媒体类型 `image/*`），用既有命令 `adopt_image` 入卡。
- `values` 以**条目编号**为键：手机端的条目有 `id`，所以这张旁表在手机端编辑后仍然对得上（和时间线不同）。
- 条目页（点开一个条目）：封面（第一个 `image` 字段）、字段网格、正文（`description`）、图片行。

### 总览布局 v1

存卡的 `extensions['noven.layout.overview']`，值是一个**载荷引用**（`extensions` 的值类型是 `ContentRef`），载荷为 JSON：

```json
{ "version": 1, "grid": 12,
  "tiles": [ { "id": "t1", "source": { "moduleId": "<模块编号>" }, "x": 0, "y": 0, "w": 6, "h": 4, "hidden": false },
             { "id": "t2", "source": { "builtin": "recent" }, "x": 6, "y": 0, "w": 6, "h": 2 } ] }
```

- `extensions` 在交换包里原样保留，手机端不解释（符合「未知扩展保留原文引用」）；**需要补测试**：导出 → 导入后 `extensions` 与其载荷一起重新映射编号。
- 没有布局载荷时，由 `Tile` 的默认尺寸自动排版（P1 的只读总览用的就是它）。
- `grid` 的取值是 Q6，P3 开工前定。

### 预留（只占名字，不实现）

`widget.type`：`map`（载荷顶层 `noven.regions`）、`file`（引用项目文件）、`graph`、`gallery`。`extensions['noven.layout.player']`。

## C5 提案　状态：已实现（P0.2，补丁集变体）

**目标**：AI 的改动先以提案出现在画布上（新增=虚线幽灵、修改=旧值划线新值并排、删除=删除线），用户逐条接受或拒绝；每张卡可开「信任 AI」自动生效。

**实现：方案 B 的「补丁集」变体**（`proposals.ts`）。不存命令序列——命令不必确定可重放，提案只存 `targets: {目标卡 → 模块补丁}`，每条补丁是 `before`/`after` 整棵模块子树快照 + 位置（`parentId` + 兄弟序号 `index` + 后继锚点 `beforeId`）：

- 预览 = head + 全部补丁（`proposalPreview`，AI 后续命令与 `preview=1` 的 GET 都以此为基底）。
- 接受 = 把补丁套到**当前** head 再提交为新修订（`commitDocument`）；人在挂起期间的编辑落在 head 上，天然与提案隔离——方案 A「人保存连带提交草稿」的陷阱不存在。
- 逐条 = 按 `moduleIds` 挑选补丁；父补丁的 after 快照连带其后代补丁一并消耗。卡层补丁（改名/外观）与角色补丁只在整份接受时生效。
- `stale`：`changes` 里标记「人在挂起期间改过同一模块」——接受会覆盖人的编辑，UI 必须明示。

`proposal.json` 在卡目录里（Finder 可见、随卡搬家、软删保留），`version: 1`。

**路由（已实现）**

| op | 请求 | 响应 |
|---|---|---|
| `diff` | `{cardId}` | `{pending, source, baseRevision, changes: [{targetId, moduleId, name, kind: 'added'\|'removed'\|'changed'\|'moved', stale}]}` |
| `accept` | `{cardId, moduleIds?}`（省略 = 全部） | `{ok, revision, version}` |
| `reject` | `{cardId, moduleIds?}` | `{ok, revision}` |
| `trust` | `{cardId, mode: 'propose'\|'auto'}` | `{ok, aiTrust}` |

`GET /card` 新增：`?preview=1` 返回叠加提案的文档；回执带 `hasProposal`、`proposal.changes`、`aiTrust`。

**信任开关**：已实现于 `trust.ts`——`library.json` 的 `cardMeta[cardId].aiTrust`（默认 `propose`），**不进卡本体**。

**AI 工具的回执**：已实现——提案模式下 `status: 'proposed'` + `pending: true` + `proposal_changes` 清单 + `next`（明示不得宣称已完成）；`auto` 档维持 `status: 'saved'`。

## C6 内容树聚合 API　状态：已实现（P0.6，`tree.ts`）

`GET /api/noven-tree?session=<会话编号>`（或 `?root=<项目目录>` 直取；只读，可轮询）：

```json
{
  "revision": "<单调变化的字符串，任一来源变化即变>",
  "cards": [
    { "cardId": "…", "name": "蛮荒-404", "kind": "WORLD", "revision": 12, "pending": false, "cover": "<资源引用或 null>",
      "modules": [ { "id": "…", "name": "时间线", "type": "timeline", "children": [] } ],
      "characters": [ { "id": "…", "name": "艾莉缇" } ] }
  ],
  "docs":  [ { "path": "文稿/第一章.md", "title": "第一章 降临", "mtime": 1790000000000 } ],
  "works": [ { "path": "作品/交互地图页/index.html", "title": "交互地图页", "kind": "html" } ],
  "files": { "count": 123 }
}
```

- `type`：`document`（无 `widget` 的文字模块）、`timeline`、`collection`、`html`，其余未知类型原样回传 `widget.type`。
- 来源：`CardStore.list/open`、`library.json` 的 `works`（`kind: 'text'` → 文稿，其余 → 作品；`archived` 不进树）、`文稿/` 目录扫描兜底（已登记的不重复）。**空分组不返回**。`files.count` = 刨掉 `卡/`、`文稿/`、`.noven`、`.git`、`node_modules` 与已登记文件后的散件数（封顶 20000）。
- `revision` 是 16 位 sha256 token（卡名+修订+pending、账本修订、文稿/作品 mtime、文件计数混成）；`?since=<token>` 相同回 304。沿用 sidecar「修订号轮询」的做法，不开新的推送通道。
- `pending` = 该卡有挂起提案；幽灵模块不进树（树永远是 head）。

## C9 归属与切换　状态：定稿（2026-10-13 用户原话）

> **界面绑定会话，内容绑定项目。**

- **导航和内容树是项目域**——同项目下所有会话看到的是同一份树、同一份文件列表，因为它们是内容不是视角。
- **"开着什么"是会话域**——画布上开哪些标签、当前选中哪个对象、正在编辑哪一块，是每个会话自己的工作现场。

推论（实现时的判据）：

- 切换会话 = 整套界面换到那个会话的工作台：抽屉亮其项目的内容树（同项目时树不变），画布换到该会话自己的标签现场。
- "有什么"是项目的；"在看什么"是会话的。持久化的界面状态（画布标签集、活动标签、选中、编辑焦点、抽屉开合）按会话分域，跨会话、跨项目都不串。
- **位置不固定**：导航栏/抽屉/画布/会话是四个语义角色，不是固定方位——用户可拖拽重排（上游 `unitSide`/`canvasSide` 即是此机制）。默认摆位是"导航栏 | 抽屉 | 画布 | 会话"，但实现与文档都不得按固定左右写死；说"抽屉"指角色，不指左边第二栏。
