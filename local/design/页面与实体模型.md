# 页面与实体模型

> 本文记录 2026-02 一轮讨论拍板的模型结论，是 [迁移任务书](迁移任务书.md) 在「画布 + 页面 + 实体」方向上的细化。
> 与任务书冲突处以本文为准；并入任务书时在其 §13 留痕。
> 每节标状态：**已拍板**（方向定死，可开工）/ **草案**（细节开工时定）/ **预留**（只占名字）。

## 0. 一张图记住全部

- **三层**：热工作（活在服务里）/ 温快照（源缓存，退订不丢）/ 冷渲染（页组件，可随便卸载）。
- **两轴**：结构轴 = 我们自己的文件夹（无限嵌套）；呈现轴 = 每个节点挂的视图元数据。
- **一个原则**：语义视图是投影，文件是真相；休闲用户走默认路径，老手永远能踏进文件层。

---

## 1. 实体模型：文件夹 + 呈现轴　状态：已拍板

- 一切实体是文件和文件夹，可无限嵌套。**卡不是对象类型，是一个恰好被渲成卡的文件夹**；世界、角色、文稿、漫画、分组、项目本身同构。
- 每个节点挂一份呈现元数据，三选：`隐藏` / `按文件展示` / `按模块展示`（卡·文档·时间线·地图·集合…）。元数据是项目数据，落在文件夹内的配置文件里。
- **呈现是用户的自由**：AI 注册、导入识别都只能给默认或建议，用户随时可覆盖（把文件挂成模块、把模块翻回裸文件、把散件藏掉）。
- 三个平级客户端写同一批文件：表单编辑器、手改文件（含用 Cursor/VS Code 指着项目目录开）、AI 工具。AI 是第三个用户，不是守门人。
- 「查看源文件」是每个语义视图的一级出口（卡页 ⋯ → 在树中显示 / 打开 manifest）。
- 嵌套免费：卡目录里的 `assets/` 等子目录也是节点，各自可挂呈现。

## 2. 页面模型：页 = 实体化身　状态：已拍板

- 页签**绝对单开**：按实体 key 去重，同一实体再点 = 跳回已有页签，不开第二个。
- **关页 = 停止这件工作**；切走 ≠ 关闭，只是不当前。
- 页自带四件套：数据源、操作面（自己的菜单/工具）、持久键、渲染体。跨页动作走共享命令面（EditorCommand 等），不把功能挂回树上。
- 树和分组退化为**纯导航索引**：点开 = 跳页；模块的重命名/归档/嵌入等操作挪进页内。
- 页签状态四词（镜像实体态，页不发明状态）：
  | 态 | 源 | 表现 |
  |---|---|---|
  | 工作中 | 会话 running / 保存中 | 克制的呼吸点动画（不要加载圈） |
  | 待决 | 卡 pending 提案等 | 绿点 |
  | 出错 | 读失败 / op 被拒 / 会话错误 | 红点 |
  | 未保存 | 文稿 dirty | 灰点 |
- **非当前页整页卸载、零渲染**；后台内容含视频/循环动画也暂停，没有「挂着不画」的中间态。
- 工作续命在服务层（会话队列、生成任务、文件写入），页死活无关。
- **回来不白屏**：源的快照按实体键缓存、退订保留；页重挂先渲旧快照，后台再刷。组件内 `fetch→useState` 的「挂载即 loading」模式要收编成按键缓存的温层源。
- 常订阅仅限导航粮（会话列表、树、绑定状态）——它们服务「开关」本身，不能页化。

## 3. 会话三视口　状态：已拍板

**实体轴**（是什么）与**渲染轴**（套什么皮、摆在哪）正交：

| 视口 | 实体 | 记忆 | 用途 |
|---|---|---|---|
| 会话页 | session | 自身 | 主对话 |
| 侧边对话 | 子会话 fork | 建时继承父会话全量日志（boundary 分界），之后独立 | 岔出去问，不弄脏主线 |
| 小窗 | 同 session 第二视口 | 持续互通（转录源按会话缓存共享，天然同一份） | 同条对话换个地方看/说 |

- 侧边对话的机制**已实现**在 `dsh-better-sidebar`（`SideChatView`/`sidechat-core`）：child session + 父日志 seed + boundary prompt；答案留在侧线。**不加回传动作**（已拍板）。
- 小窗**未实现**，且不需要专门机制——画布分屏后「同 sessionId 开两个视口」白拿记忆互通。
- 手机模拟器是渲染轴上的一层皮：任何会话可套，多开模拟器 = 换会话，不做专门多开。
- 会话页、侧边对话、小窗都是画布里的页/分栏；浮窗形态以后如需再加，不阻塞。

## 4. 画布：布局树　状态：已拍板（先两向）

- 结构：叶 = 页签组（各自页签条 + 活动页），节点 = 分割（方向 + 比例）。拖页签到叶子边缘 = 该方向插新叶；组间拖 = 移动。
- 先做左右/上下两向分；四宫格、九宫格是同一棵树的自然延伸，不另行设计。
- 每叶仍只渲活动页，§2 的页模型一行不改。
- 白拿的场景：同会话双视口（小窗）；手机渲染 + 原始流并排；对话框 + 被改实体并排。

## 5. 导入契约　状态：已拍板

- **包不是实体，文件夹才是**。压缩包 = 文件夹的序列化形态；识别出嵌套结构就展成文档架（目录树），不当整块不透明物。
- 传输格式两种（出墙才用，不是日常动作）：
  1. `.nvcard` 单文件 JSON：manifest + fields 内联 + assets base64，自包含、可 diff；
  2. `.card` 目录原样 zip：解开即盘上形态，零转换。
- 酒馆 PNG / chara JSON 等外来格式**只进不出**：导入转成我们的实体，导出只出 `.nvcard` / zip。
- 导入流程：
  1. 选文件 → **只分析不消化**：报告「认出 N 张卡 + M 团未识别」；
  2. 用户选落点（树的分组/文件夹，可当场新建）；
  3. 如实落位：认出的挂默认视图（卡包 → 卡视图），未识别的就是裸文件原样展示——没有「导入失败」态，只有「没挂视图」；
  4. 之后每节点呈现随便改（§1）。
- **休闲路径零认知**：单卡包（酒馆 PNG）不进解开视图，拖入 → 直接一张卡 → toast「已导入 X」+ 打开 + 撤销。多卡包的解开视图用**卡的语言**（卡名/头像/世界书条数）不用文件语言；「整包导入」是默认钮，挑件拖是可选捷径。
- 识别路由硬规则：含卡数据的 PNG 进卡通道，永不落成 HTML/文本源码预览；识别不出的 PNG 按图片预览。
- 半识别 = 如实报告：解析出卡但没消化完的字段以原文件留在卡目录内，manifest 标出未消化部分。
- 多卡世界大包 → 映射成「一个分组/文档架里多张卡」，不揉成一张巨卡；manifest 支持多卡声明时再定稿。

## 6. 拖动模型　状态：已拍板

- **拖动不干活，落点解释**。载荷 = 实体引用（卡路径 / 目录路径 / 会话 id / 外部文件），落点声明收什么。

  | 拖什么 | 落到哪 | 干什么 |
  |---|---|---|
  | 树里一张 `.card` | 手机屏 | 绑定到这台模拟机 |
  | 树里一张 `.card` | 画布 | 开卡页 |
  | 卡段下的目录（成组的多卡） | 同上 | 整个目录当一个卡包（虚拟打包） |
  | 外部包文件 | 侧栏 | 解开挂载成可浏览节点 |
  | 解开的包根 / 包内单项 | 树里落位 | 导入（拖根 = 整包，拖单项 = 只导那件） |

- **目录 = 隐式包**：拖动目录名时拖拽动作现场虚拟打包，用户永不需要先压 zip。打包只在出墙（导出/发给别人/跨项目）时发生。
- 语义分界：应用内落点 = 引用或移动（不复制实体）；拖出应用（桌面/其他软件）= 现场导出成 `.nvcard` 或 zip。

## 7. 底排与功能台　状态：已拍板

- 底排分半：`＋ 新建` | `🔧 工具`。
- 新建菜单六项：
  | 项 | 落点 |
  |---|---|
  | 新建分组 | `mkdir` op（可拖进 `__misc__` 成组） |
  | 卡 | 对话框内选 kind：世界 / 角色 |
  | Studio | 建 `模-` 会话（模拟器同款链路） |
  | 文稿 | `文稿/名.md` |
  | 漫画 | `漫画/名.html`（目录即分组） |
  | 导入 | §5 流程 |
- `🔧 工具` = 功能台：六条真 slash 命令（整理卡/研习/画地图/画漫画/文游生成器/写作）+「从当前对话岔一条侧线」（走 better-sidebar `sidechat.create` 拿 child sessionId 开页）。
- 分组删除：`rmdir` op（服务端已实现），UI 确认时给文件计数。
- AI 可自建分组：目录语义天然支持，顶层内容无需注册表——AI 写新目录 = 新分组自动出现。

## 8. 落地顺序　状态：已拍板

1. **温层基座**：源缓存 + 快照保活的通用模式收编组件内 fetch（`listDir`/`readDoc`/文档脏态）；模拟器视图态收进画布 store。
2. **页功能内收**：树行操作挪进页内；底排分半接功能台；树加 Studio 虚拟组与分组删除。
3. **卡页模块分页**：每模块 = 独立页面（兑现「不打开的模块不渲染」）。
4. **分屏布局树**：CanvasState 从 tabs+active 升级为布局树。

## 9. 双角色验收原则

两个考题的结论，验收每一屏都过一遍：

- **休闲用户**（不懂计算机的酒馆用户）：默认路径零认知——拖 PNG 进来就是一张卡，永远不该看见 HTML 源码和 manifest；撤销永远在手边。
- **老手**（擅长 AI、会手改）：文件真相永远可达——每个语义视图一步踏进文件层；AI 处理的结果能逐文件检查、徒手修正；我们不比 Cursor 差的方式只有一种：文件不藏。

## 10. 待决与预留

- 工作动画的具体样式（呼吸点之外是否分任务类型）——草案。
- `.nvcard` 字段规范、多卡 manifest 声明——草案，首批遇到真包时定稿。
- 浮窗（画布外随身视口）——预留。
- 项目切换时的过渡（闪空 vs 按项目分桶缓存）——草案。
