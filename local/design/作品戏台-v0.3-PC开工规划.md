## 1. 背景：为什么有 v0.3

- **v0.2** 按「绍宋」形态设计：舞台岛 + 原生磨砂叙事层 + 原生输入栏。磨砂层是"岛没法替换输入层"的补偿，既破坏沉浸，也不好做。
- **产品决策（2026-10-12）**：真正的大需求是**界面全改的全屏前端作品**。作品自带输入层，磨砂层取消，作品作为卡模块挂在世界卡或角色卡上。
- 因此作品必须能拿到叙事流、能发送用户输入并知道结果、知道键盘状态、知道本局角色、在分支切换后拿到正确的事实。v0.2 一项都没有。
- **兼容原则**：电脑向手机妥协（能力上限 = 手机，基线 Chromium 111），手机向电脑看齐（协议在 PC 先定义、先预演）。所以 **PC 是协议的参考实现**：PC 做错了，手机会跟着错。这也是本规划强调"纯函数 + 黄金样例"的原因。

## 3. 关键设计决策与理由

### 3.1 帧的构造是纯函数，两个模拟器共用

**做法**：新建 `stage-frame.ts`（不含 React），导出：

- `buildEnv({ sizeKey, imeOn, webview })` → `env`
- `frameReason(prev, next, ctx)` → `'init' | 'turn' | 'query' | 'branch' | 'ime' | 'send'`
- 键盘高度表 `SIM_IME`、基线常量 `WEBVIEW_BASELINE = 111`

**为什么**：WorkTab 和 ChatTab 现在各写一份 `frameBase`，已经开始分叉（ChatTab 少了 card/state/archive）。v0.3 帧字段翻了一倍，两份写法必然漂移；而 PC 是手机的参考实现，漂移会传染过去。纯函数还能直接单测。

### 3.2 `env.webview` 默认上报 111

**做法**：模拟器上报的内核版本默认是 `111`，可切换为"实际版本"（从 `navigator.userAgent` 解析 `Chrome/(\d+)`）。标红永远按 111 判，和上报值无关。

**为什么**：PC 浏览器内核远高于 111，如实上报的话，作品的降级分支在 PC 上永远跑不到，作者测不到。回执 §B2 已承诺。

### 3.3 transcript 解析 = 纯函数 + 黄金样例，样例才是规格

**做法**：新建 `stage-transcript.ts`，导出 `buildTranscript(messages, castNames)`。样例放在 `noven-shell/tests/fixtures/transcript/*.json`（`{ name, cast, input: [消息], expected: [段] }`），由 `tests/transcript.mjs` 跑。

**为什么**：r2 B1.0 写死了"解析规则以共享黄金样例为准，不以任一端代码为准"，回执 E5 承诺 PC 起草首批。两端各写一个解析器，必然有差异；有了样例，差异才能判定归属（r2 §A：没被样例覆盖的差异不算手机缺陷）。

### 3.4 档案真相源 = 会话日志，快照只是缓存

**做法**：新建 `stage-archive.ts`：

- `collectDeltas(entries)`：从会话事件里按顺序收集增量：①助手消息里的 `novex-use` 信封（用 `renderBlocks`/`parseNovexUse`）；②查证回写注入事件（步骤 5）。每条带 `messageId` 和 `seq`。
- `foldArchive(seed, deltas)`：在种子上按顺序合并出当前 archive/state。
- `<页面名>.stage.json` **降为开局种子**：只在没有任何增量时提供初始档案。

**为什么**：v0.2 定的"快照落工作区文件"在分支面前是错的：PC 的重试/编辑是 fork 子会话，工作区文件不跟着 fork，作品会读到另一条分支的事实。会话日志本身就带分支语义（fork 继承祖先、兄弟互不可见），从日志重放，分支隔离就是免费的，不用另造一套 branchId 存储。这也是仓库规矩"模型可见 ⟺ 进日志"的直接推论。

**性能**：先做内存折叠，测一下 200 回合会话的耗时；**超过 100ms 才做**快照缓存（键 `(sessionId, 最后增量 seq)`，落 `.noven/stage/<sessionId>.json`）。回执 E4 写的是"超出预算再分段"，没超就不建缓存。

### 3.5 `send` 在浏览器版不做手势门控，只打日志

**做法**：限频（同一作品两次发送间隔 ≥ 1s）、长度上限、`input:"own"` 检查都要做；手势门控不做，每次 send 记进 WorkTab 调试盘。

**为什么**：沙箱 iframe 里的页面脚本可以绕过 helper 直接 postMessage，父壳无法验证手势，在浏览器里做门控是安全表演。回执 E2 已定：浏览器版（开发预览）只打日志，桌面包（Electron）再用输入事件门控。**桌面包门控不在本规划范围内**。

### 3.6 分叉要继承画布页签（B6 的前置）

**现存问题**：`branches.tsx` 分叉后打开子会话，但画布页签按 owner 会话切片（`CanvasTab.owner`），子会话的画布只有「起点」。用户在作品页签里玩着，回原生层点重试，回来作品页签没了。B6 的 `reason:"branch"` 在 PC 上根本没有机会触发。

**做法**：分叉成功后、`openSession(child)` 之前，把父会话的页签和布局复制一份给子会话（新增 canvas action，例如 `inheritOwner(parent, child)`：tabs 换 owner 后复制，layout/focus/floats 照搬）。`branches.tsx` 拿不到画布 store，需要经由 `index.tsx` 传一个回调进 `applyBranches`。

**为什么放进本规划**：没有它，B6 在 PC 上无法验收。**但它改的是分支行为，执行前单独向用户确认**（见 §5 待决 D1）。

### 3.7 查证回写 = 宿主侧隐藏注入，锚定当前助手消息

**约束**（回执 §B3）：回写是 `source.kind` 非 `'user'` 的隐藏注入事件，锚定发起查证时的那条助手消息 id；PC 承诺重试/编辑/分支定位跳过非 user source 的消息（`branches.tsx` 的 `lastUserPrompt` 已经按 `source.kind==='user'` 过滤，要复核其余路径）。

**怎么跑查证轮还没定**，见 §5 待决 D2。**步骤 5 在 D2 拍板前不开工**。

## 4. 施工步骤

### 步骤 1：帧骨架（`env` / `reason` / `turn` / `scene`）

**目标**：两个模拟器下发的帧带上 `env{platform:'pc-shell', bridgeVersion:2, webview, ime{visible,height}}`、`reason`、`turn{status,queued}`；补齐 v0.2 欠账 `scene` 的 `?from`。

**改动**：

1. `stage-frame.ts`（新）：`buildEnv`、`frameReason`、`SIM_IME`、`WEBVIEW_BASELINE`、`realWebview()`。
   - `SIM_IME` 按回执 E3：`p360:280, p390:300, p430:320, t768:320, t834:340, t1024:300`（CSS px）。
   - `frameReason` 规则：首帧 `init`；会话 id 变了 `branch`；`env.ime` 变了 `ime`；本次是 send 回执 `send`；转录变了 `turn`；查证回包 `query`（步骤 5 才有）。同时有多种变化时按 `branch > send > query > ime > turn` 取一个。
2. `stage-island.tsx`：`IslandFrame` 加 `env`、`reason`、`turn`、`transcript`（步骤 2 用）、`choices`、`cast`（步骤 7 用），先加类型；`StageIsland` 推帧时把 `reason` 放进 patch。
3. `canvas.tsx`：
   - `CanvasState` 加 `simIme?: boolean`、`simWebview?: 'baseline' | 'real'` 及对应 actions；读取用 `??` 兜底（理由见 §0.2）。
   - WorkTab 手机档工具条、ChatTab 机框工具条加两个开关：「模拟键盘」「内核：111/实际」。选中态走统一规则（`aria-pressed`），文案进 locale。
   - 模拟键盘打开时，模拟器底部画一块高 `SIM_IME[size]` 的占位键盘（中性灰，写"模拟键盘"），岛区相应缩短。这就是 B3 要求的"作品区抬升"在 PC 上的预演。
   - `turn.status` 取 `transcript.busy ? 'streaming' : 'idle'`；`turn.queued` 取本地已发出、但还没被 `turn/start` 消化的发送计数（PC 客户端拿不到服务端队列长度，回执 §B4 写的"如实上报"以此近似，**在代码注释和汇报里说明这是近似值**）。
4. `scene` / `?from`：`islandDoc` 的 `N.query(d, i, from)` / `N.compose(t, from)` 加可选的第三/第二参数，`IslandCall` 加 `from`，调试盘显示出来。

**验收**：在体检岛做好之前，用一个临时 HTML 作品打印 `NOVEN_FRAME` 和每次 `noven:frame` 的 `reason`。切换键盘开关应收到 `reason:"ime"`，`env.ime.height` 和档位对应；内核开关切换后 `env.webview` 在 111 和实际版本之间变化。

**测试**：`tests/frame.mjs` 覆盖 `frameReason` 的优先级和 `buildEnv` 的档位映射。

### 步骤 2：黄金样例 + `transcript` 生产

**目标**：帧里有 `transcript`（段结构见 r2 B1），`messages` 保留（标为弃用，v0.4 才移除）。

**先写样例，再写解析器。** 首批样例（回执 E5）至少包括：

| 样例 | 要点 |
|---|---|
| 纯旁白 | 空行分段，每段一个 narration |
| 单人台词 | `阿七：……` 在名册内 → dialogue，speaker=阿七，正文不含"阿七：" |
| `@` 写法 | `@阿七：……` 同上；句中 `@阿七` 不触发 |
| 多人台词 | 连续几行不同说话人 → 各自成段 |
| 误判（写明在预期内） | 名册里有名为「注」的角色时，`注：……` 判为台词；样例照实写出期望值 |
| 名册外 | `路人：……`（路人不在名册）→ narration |
| 安全子集 | `**粗**` → `<b>`，`*斜*` → `<i>`，换行 → `<br>`，其余（含 `<script>`、`<img>`）全部转义 |
| 协议块剥离 | 正文夹着 `novex-def` / `novex-use` / `novex-skin` 围栏、`<UpdateVariable>…</UpdateVariable>` → 不进 transcript |
| 出图 | `![](asset-id)` → `kind:'image'`，`src` 为 id |
| 用户消息 | role=user，单段 narration |
| 段 id | `id = "<messageId>#<n>"`，`n` 从 0 起 |

**流式中间态由手机侧补**（回执 §E1）。PC 的 `transcriptSource` 只读已提交的 `assistant/message`，没有流式中间态，所以 **PC 产出的 `streaming` 恒为 `false`**。要在汇报和代码注释里写明这是 PC 已知差异；接流式需要读流帧，不在本步范围内。

**改动**：

1. `stage-transcript.ts`（新）：`buildTranscript`。剥协议块复用 `stage-artifacts.ts` 的 `renderBlocks`（只取 `type==='text'` 的块再切段），不要另写一套围栏解析。`UpdateVariable` 标签另行剥除。
2. `index.tsx` `transcriptSource`：`TranscriptMsg` 加 `seq`（`messageId` 用 `String(seq)`）。
3. `stage-phone.tsx`：帧里同时下发 `transcript` 和 `messages`。
4. `package.json` 加 `"test": "node tests/frame.mjs && node tests/transcript.mjs …"`（先 tsc 再测，测的是 `lib/client/*.js`）。
5. 样例要交给手机侧：完成后告诉用户样例路径，由用户转交。**不要往 Novex-Development 仓库里写代码文件。**

### 步骤 3：`send` + `sendResult` + `input:"own"` + `ready()`

**目标**：自带输入层的作品能发送并拿到回执；画不出来会自动退回原生。

**改动**：

1. `stage-artifacts.ts` `parseDefAttributes`：认 `input="own"`；`NovexDef` 加 `inputOwn: boolean`。
2. **作品文件（WorkTab 打开的 `.html`）怎么声明 own**：协议只写了"def 元信息 / 作品清单"，作品文件没有 def。→ 待决 D3，拍板前先只支持 def 声明。
3. `stage-island.tsx` `islandDoc`：
   - `N.send = function(t){ post({ noven:'send', text:String(t==null?'':t) }) }`
   - `N.ready = function(){ post({ noven:'ready' }) }`
   - `IslandCall.kind` 加 `'send' | 'ready'`；`StageIsland` 的 message 处理分发这两种。
   - ready 超时：`fillParent` 模式下挂载后开一个 8s 计时器，收到 `ready` 就清掉；超时或收到 boot 阶段的 `err` 时回调 `onFallback`。非全屏（转录内）的岛不计时，仍按高度回报判断（r2 B7 兼容条款）。
4. `stage-phone.tsx`：
   - 当前舞台的作品声明了 own 时，隐藏底部 `nv-pcompose`。
   - 收到 send：依次检查 not-own → length（与输入栏同一个上限常量，没有就新定义一个并写注释）→ rate（距上次 < 1s）。通过的调 `ask(text)`（`'queue'` 模式，生成中排队）；`result` = 发送时 `busy` ? `'queued'` : `'accepted'`。推一帧 `reason:'send'` + `sendResult`。被丢弃的也推回执，`why` 写明原因。
   - 每次 send 都上抛 `onCall`，WorkTab 调试盘记一行（这就是浏览器版"只打日志"）。
   - `onFallback`：收起舞台（`setStageOpen(false)`），显示提示（locale：例如"作品没有响应，已切回对话"）。
   - 内容照常进原生对话：`ask` 本来就是往本会话 prompt，天然满足。
5. B4 规定"点选项走 send"，这是作品自己的事，宿主不用特殊处理。

**验收**：写一个声明 own 的测试件，自带输入框，并在首屏调用 `ready()`。验证四点：发出的消息出现在原生对话里；连点只有第一条被接受（其余 `rate`）；模型生成中发送返回 `queued`；去掉 `ready()` 后 8s 自动退回转录视图。

### 步骤 4a：分叉继承画布（需用户先确认 D1）

### 步骤 4：档案改由日志重放（B6）

**目标**：帧里的 `archive/state/deltas` 来自当前会话日志的折叠；`.stage.json` 只当开局种子。

**改动**：

1. `stage-archive.ts`（新）：`collectDeltas`、`foldArchive`。
   - 合并语义：**待决 D4**（增量里的数值是绝对值还是相对值；v0.1 的例子 `"strength": -3000` 有歧义）。拍板前按"同 id 覆盖字段（绝对值）"实现，并在测试里把这个假设写成显式用例，方便以后改。
   - 每条 delta 输出 `{ messageId, seq, data }`；帧的 `deltas` 取最近 N 条（N 定成常量，建议 50，写明理由：与 transcript 窗口同量级）。
2. 数据来源：WorkTab 现在用的是画布 owner 会话的转录（`useTranscript`），ChatTab 用的是模拟会话的转录（`useSimTranscript`）。折叠需要原始事件里的 `novex-use` 文本。方案是在 `transcriptSource` / `simTranscriptSource` 的折叠里顺带产出 deltas，或者新增并列的 hooks 快照源。**不要在组件里订阅事件流**（违反 §0.2）。
3. `WorkTab`：`frameBase` 的 archive/state 改为 `foldArchive(stageJson 种子, deltas)`。

**验收**：①一条会话里先后两条助手消息各带一个 `novex-use`，作品看到的是合并后的档案；②在第二条之前分叉（步骤 4a），子会话的作品只看到第一条的结果，并收到 `reason:'branch'`；③200 回合合成数据的折叠耗时打印出来，超过 100ms 再按 §3.4 加缓存。

**测试**：`tests/archive.mjs`：顺序合并、种子兜底、分支截断（给定事件截到某个 seq 等价于分叉）。
