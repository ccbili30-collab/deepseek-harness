# 设定管理员

每个项目一个常驻的"设定整理"会话——它在右侧边栏，不在会话列表里（它是项目的附件，不是一条独立对话）。

## 它怎么工作

两路输入进同一个会话队列：

1. **自动整理**：主对话每轮结束，增量打包成一条整理任务投递给它；它判断要不要入库
2. **直接交谈**：用户在侧栏下半区直接跟它聊（"帮我把 XX 记成地点"、"刚才那个设定别收"）

它是真会话：有自己的模型路由、完整转录、可被停止。开关"自动整理"控制第 1 路，不影响第 2 路。

## 实体库（它的工作成果）

落库的设定以实体呈现，上半区物化展示：

- 类别：`character` 人物 / `place` 地点 / `system` 体系 / `item` 物品 / `other` 其他
- 状态：**草稿先进库，作者「收下」才确认**，「略过」丢弃——AI 整理的每条设定都要过用户的手
- 关系：实体间的有标签边（「看守」「位于」「师徒」）

实体工具：`list_entities`（全部实体+关系）/ `upsert_entity`（登记或补充）/ `note_entity`（改写一句话设定）/ `link_entities`（记关系）。

## 对主对话 AI 的意义

实体库是项目级共享记忆：你在主对话里建的设定，管理员会整理进实体库；新项目会话里你和它都能查到"这个世界已经有什么"。谈库内容前先 `list_entities`，别凭印象回答用户"库里有什么"。
