# 项目与挂载

## 项目 = 文件夹

- 项目就是一个目录 + `.noven/project.json` 身份标记；搬目录、改目录名都不丢身份
- `~/.noven/` 里的项目注册表是索引：`list_projects` 列出全部注册项目（名字/编号/目录/卡数）
- `project` 参数三种写法：项目名、项目编号、绝对路径；未注册但存在的目录也认

## 挂载：会话和卡的四种关系

用户在创作面板里给会话挂卡，每种角色语义不同：

| 角色 | 含义 |
|---|---|
| 回答身份 | 这张角色卡是 AI 的人格 |
| 背景 | 只读喂给上下文的世界观卡 |
| 管理对象 | 本会话要动的那张卡，带权限档 |
| 引用 | 别的项目的卡，留在原处只挂过来看 |

管理对象的权限三档：`read`（只读）/ `approve`（改动要确认）/ `free`（放手改）。

**挂载信息每个回合注入给你**：角色、卡名、编号、修订号、摘录、`card_dir` 绝对路径都在注入里。判断"有没有挂载"以注入为准，不是以 `list_cards` 为准（它只列项目卡库）。

## 引用卡不是二等公民

- `read_card`/`read_text_block`/`read_card_image` 对引用卡照常工作
- **写也通**：`rename_card`、`write_module_text` 等写工具对引用卡直接生效——改的就是来源项目的卡，用户意图已经很明确了
- 你改过的跨项目卡会自动进本会话引用清单（动过它就诚实可见）

## move_card：搬卡

```
move_card { card_id, to_project: "this" }   # 搬到本会话项目
move_card { card_id, to_project: "ceshi" }  # 搬到指定项目
```

- 整目录搬家：编号、内容、修订历史、载荷原样随行
- 搬到本项目自动摘引用（变本地卡）；搬到别处引用自动指向新根
- 省略 `project` 参数时自动在全部项目里找这张卡

## 删除与自愈

- 删卡不走软件（用户在 Finder 删目录也合法）——本地挂载（身份/背景/管理对象）指向已删的卡会**自动摘除**，不会留幽灵
- 引用卡目录暂离（项目搬家/断开）会标 `missing`——**不摘**，它会回来
- 用户数据默认不删：除非用户明确要求，否则先说明影响再确认
