# 排查与自愈

遇到"找不到"先走诊断链，别急着下结论也别绕过工具改文件。

## 卡不存在

```
list_cards                  → 看本会话项目卡库
list_projects               → 看全部注册项目
list_cards { project: "…" } → 看指定项目
```

错误信息里会直接列出已注册项目清单。跨项目的卡还能通过挂载引用直接访问（注入消息里有 `card_dir` 绝对路径）。

## 版本冲突（写卡被拒）

`版本已变化（当前 vN）` —— 报错本身给了正确版本；或 `read_card` 重拿 `draft_version`/`next_draft_version` 再写。这是并发保护不是故障，接力写就是。

## 挂载异常

- 挂载清单显示 `（卡不存在）`/`missing: true`：本地挂载会被自动摘除（卡真没了）；**引用**挂载标 missing 但保留——来源项目目录可能搬家/暂离，会回来
- 找不到挂载卡的路径：挂载注入和 `list_cards` 的 `mounted` 里都带 `card_dir`，不用 `find`

## 文件层面的心智模型（修之前先看这层）

| 位置 | 归属 | 丢了会怎样 |
|---|---|---|
| `卡/`、作品文件、工作台目录 | 用户数据 | 真丢了，先问用户 |
| 项目内 `.noven/`（身份、实体库） | 应用小状态 | 可重建，但别替用户删 |
| `~/.noven/`（注册表、绑定、登记） | 应用索引 | 只是索引，文件还在 |

诊断顺序：**先用工具**（list_cards / list_projects / list_library），**再看文件**——工具有语义，文件没有。反过来的顺序（先 find 后工具）会绕过版本控制和回执，是最差路径。

## 工具行为异常

工具返回明显异常（比如只剩一个状态词、缺了它承诺的字段）时：先原样重试一次——可能是瞬态；仍异常就如实告诉用户"工具返回不完整"，别自己编补齐缺失的字段。

## 手册本身

`help()` 回目录。发现手册内容和实际行为对不上：手册可能滞后——以工具实际返回为准，并向用户说明出入。
