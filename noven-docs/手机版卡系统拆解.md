## 1. 产品决策（docs/PRODUCT.md，已定稿不是提案）

**只有两种卡类，共用同一套模块化内容底座：**

- **世界卡（WORLD）**：提供世界背景与设定，可直接开聊（不需要先建角色卡）
- **角色卡（CHARACTER）**：提供角色人格，可独立使用，也可**作为世界内角色被引用**

卡必须支持：人工创建编辑；模块新增/删除/排序；横向与竖向模块；**模块嵌套**；图片资源；预览与保存；导入与导出；删除；**AI 读取和修改**。

三条核心原则：
1. **卡片编辑与卡片使用分开**（使用资料 ≠ 拥有修改权限）
2. **背景注入、角色身份、管理权限三分开**（世界卡给背景，角色卡给人格，管理权限只授权 AI 改指定卡——不会自动把全部内容注入对话）
3. **模式不是卡类**；暂不做分对话

AI 修改纪律（五条军规）：读最新保存内容；草稿必须明确处理；同一张卡避免并发覆盖；**保存成功才能报告完成**；完成入口必须打开真实对象。

## 2. 数据模型（content-core/ContentDocument.kt，153 行纯数据）

```
ContentDocument（= 一张卡）
├── id / kind(WORLD|CHARACTER) / name
├── modules: List<ContentModule>        ← 模块树，数组顺序即顺序
│   ContentModule
│   ├── blocks: List<ContentBlock>      ← text 块（正文引用）/ image 块（资源+可选图注）
│   ├── children: List<ContentModule>   ← 递归嵌套
│   ├── layout: VERTICAL | HORIZONTAL
│   ├── tags: List<String>              ← 无空串、无重复
│   ├── use: always | manual | keywords{words, caseSensitive, requireAll}   ← 携带规则
│   ├── routing: DEFAULT | PER_TURN | STYLE | STANDBY                      ← 去向（注入协议）
│   ├── temporality: CONSTANT | SNAPSHOT                                    ← 压缩后可否重注入
│   └── characterIds                     ← 角色展示位（世界卡专属）
├── resources: List<CardResource>       ← 图片等，id + ContentRef + mediaType
├── internalCharacters: List<ContentDocument>  ← 世界内角色（递归完整卡；角色卡不得再嵌）
├── appearance: avatar/cover(引用本卡资源) + readingLayout(PAGED|CONTINUOUS)
└── extensions: Map<String, ContentRef> ← 未知扩展保留原文，不解释不改写
```

- **ContentRef**：正文/图片只是引用，结构里不内嵌字节——大正文流式可复制
- **校验**（validate）：全树编号唯一；角色不能容纳角色、世界内只能有角色卡；头像/封面/图片必须引用**本卡**资源；角色展示位必须指向本世界角色且不重复
- **人工与 AI 共用同一套变换**（ContentChange：Add/Replace/Remove/Move/PlaceModule、EditBlocks、Put/RemoveResource、SetAppearance）——不按编辑者复制业务规则

## 3. 存储与交换格式（content-storage + docs/specs/card-format.md）

**存储（CardStore）**：head + 多版本 revision + deleted 软删除；**乐观并发**（save 带 expectedRevision）；编辑租约（acquireEdit）；草稿暂存（CardDrafts，ChangeSource 含 IMPORT）；失败保留草稿不丢内容。

**交换包（导入导出，.novex.zip）**——结构与载荷分离：
```
structure.json          ← 卡结构 + contents 清单（每条 size + sha256）
图片/0000-世界.png       ← 载荷（v2 人可读命名；v1 机器格式 contents/N）
正文/0001-世界-主线.md
扩展/0002-内容.bin
```
- **宁可拒绝，不可静默丢弃**：未知字段/块类型/清单不匹配一律报错
- 导入语义：先校验 SHA-256 再转存；编号重新分配（防冲突，设计行为）；导入成**草稿**，用户确认才归库；未提交草稿不能导出
- **往返保证**（CardRoundTripReconciliationTest 守护）：导出→导入→再导出，除编号外逐项一致（模块顺序/嵌套/layout/tags/use/routing/temporality/块序/载荷字节 SHA-256/世界内角色递归完整）
- 非 Novex 文件（PNG 卡、纯文本）：整体进自由文本模块，**不强行拆字段**

## 4. AI 管卡工具面（CardToolProtocol + CardEditingTools，共 33 个）

**权限模型**：`CardToolPolicy(targets: Set<ManagementTarget>, permission: FREE|READ_ONLY|批准?, readTargets)` —— AI 只能改被授权的 (root, target) 对，读集合可大于写集合。

| 组 | 工具 |
|---|---|
| **宏通道（建卡首选）** | `create_card_bulk`（整卡一次成型：kind+name+modules 嵌套树，整包校验原子写入，错误带 JSON 路径）、`add_module_bulk`（插整棵子树） |
| 建/删 | `create_card`、`remove_module`、`remove_content_block`、`create/remove/copy_internal_character` |
| 读 | `read_card`（结构+版本，不读正文）、`read_text_block`（**按码点分页**，has_more/next_offset）、`read_card_image`（真读图不是看目录） |
| 写正文 | `write_module_text`（新建/全替换）、`write_module_markdown`（整模块 Markdown，图片用 `![说明](card-image:资源#块)` 语法）、`replace_text_range`（**码点左闭右开局部替换**，content_ref 防错版） |
| 结构 | `add_module`、`add_child_module`、`rename_module`、`move_module`、`move_content_block`、`place_module`（跨父级）、`set_module_layout`、`set_reading_layout` |
| 图片 | `save_conversation_image`（对话图存卡）、`set/clear_card_image`（封面/头像）、`insert_owned_image`、`replace_block_image`、`write_image_caption`、`remove_card_resource` |
| 元数据 | `set_module_options`（tags + use 规则 + routing + temporality）、`rename_card`、`place_internal_character`（角色展示位） |

**四个久经实战的协议设计（复刻必须保留）：**
1. **draft_version 乐观锁**：每次写操作带"读取时的版本"，冲突即拒；`saved` 返回 `next_draft_version` + **新编号直链**（created_module_ids/created_block_ids）——下一步直接引用，免回读
2. **宏通道优先**：整卡/大批量必须走 bulk（整包校验，任何节点不合法不写半张卡），逐条 add 是反模式
3. **容错解析**（每条都是真实翻车换来的）：模型把 block_id 写成 `new/create/auto/null` 等伪编号→按新建处理；module 对象被整体编码成字符串→容忍并给正确形状示例；定位字段空串=合法语义（新建/末尾），schema 的 optional 契约必须与解析层一致（曾因此 46 分钟建不出一张 6KB 卡）
4. **失败不谎报**：failed 保留草稿（preserved_draft）；只有 `saved` 才算完成

## 5. 与对话的关系（本次只记录，不复刻）

- 模块 **routing**（default 进开局资料包 / per_turn 每轮注入 / style 文风槽 / standby 待命）+ **use**（always/manual/keywords 触发）+ **temporality**（constant 可压缩后重注入 / snapshot 只出现一次）构成注入协议
- RequestCapacity 按模型真实上下文（如 128K）做携带预算，超限提示减模块/降携带/压历史
- 手机版对话运行时（ToolDialogueLoop、checkpoint、per-turn injection）与 DSH 会话体系是两套世界——注入如何嫁接是独立课题
