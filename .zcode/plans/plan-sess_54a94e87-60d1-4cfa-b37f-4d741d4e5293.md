## 1. 复述：这次交付什么

交付一轮完整的 Noven 外壳修正，而不是零散补图标：

1. **对象顶栏恢复**：对话的会话导航、视图与工具在 Agent／手作、空白／已有会话、展开／折叠中各有明确且可达的位置；画布恢复可见、统一的对象切换与工具入口，不再靠右键或偶然的自绘页面决定能力。
2. **命名统一**：以往对话叫“会话列表”，当前 Agent 过程叫“执行记录”，内容历史叫“版本”；画布的“页签条”和当前对象的“对象工具栏”分开，不再统称“切换菜单”。
3. **模式与折叠动效**：Agent／手作发生真实、连续、可中断的区域换位；顶栏、页签、折叠和菜单使用同一套克制的运动语言，并完整支持 reduced-motion。
4. **默认 Noven Web 镜像打包 macOS**：同一共享 renderer 反向采用 PC 的整栏折叠、恢复入口、标题栏几何、配色、顶栏和动效；修好后启动一套隔离 Web 并给你可打开的地址。
5. **同源码候选与证据**：相关回归、类型检查、构建、一次 Noven Test 打包与 Host smoke；交付新的 DMG/SHA256，并明确 Web 能参考什么、不能替代什么。

## 2. 目的：为什么这样做

外层三栏位置正确只是骨架。真正可用的产品必须同时保住对象能力、空间连续性和跨端可预测性。Web 的价值是成为打包 PC 的高保真开发镜像，而不是另养一套简化 UI，也不是用浏览器截图冒充 Mac 原生验收。

## 3. 已查明的根因与实施步骤

### A. 先修对象顶栏与导航

- 补上手作的小时钟／会话列表入口：复用现有完整 `sessionBrowser`，临时替换左侧内容树；选择会话后回到内容树，不改变 `mode`。Agent 中同一入口只展开并定位既有会话列表。空白会话、Create 新会话路径及手作折叠恢复区都保留必要的会话导航，内容专用操作仍按真实会话状态显示。
- 移除 Noven 对 Conversation views 的一刀切隐藏，恢复标题行与视图行的自适应高度；不粗暴取消整个 `hideChrome`，避免空白页重新出现无意义标题和内容操作。
- 为 Noven `selfChrome` 画布定义与宿主对等的可见导航：对象页签、页签切换菜单、工具菜单、关闭／全屏各就各位；不把宿主右键菜单当唯一入口，也不叠出双顶栏。
- FeatureNav、FeatureRail、内容树工具和对话工具菜单统一走同一个 `openFeature` 语义出口，避免恢复入口后又把功能开到两层不同画布。页内设备、视图、版本继续属于对象工具栏。
- 文案全部走 typed locale；仅合并确认指向同一目的地的异名，不借统一命名合并不同功能。

### B. 建立唯一的模式运动协调点

- 在 `ui-layout` 管理显式模式转场，Noven `changeMode` 仍唯一提交产品状态。纯镜像切换读取前后真实矩形，对稳定的 main/rightbar 做约 300–320ms 的 FLIP `translateX`；不 scale、不 blur、不克隆 Conversation/Canvas/终端，不改 React key。
- 快速反向时从当前视觉位置接续，旧动画不得清理新状态；首帧、Session 恢复、窗口 resize、窄屏和全屏不擅自播放。无法取得稳定几何时直接提交并以轻微淡入降级。
- Conversation／Canvas 折叠由轨道收缩、裁剪和短淡出共同完成，折叠开始即禁止交互，结束后才隐藏；不再先空白再缩栏。
- 控件反馈约 120ms，页签指示约 160–180ms，菜单约 160–200ms；区域场景使用现有共享时长并允许 Noven 覆盖为自己的 scene 档。reduced-motion 全部直接落最终状态。
- 不做 3D 翻转、弹簧过冲、整页模糊、动态 vibrancy、逐帧 React render，也不让模式动画与 grid、View Transition 三套效果同时播放。

### C. 让 Web 镜像 Mac，但把呈现与原生能力分开

- 新增独立的呈现标记（计划为 `data-chrome-platform='darwin'`），默认只由 Noven Web 设置；真实 `data-platform` 继续只由 Electron preload 所有。首帧挂载前确定，避免先 Web 后 Mac 的跳变。
- 布局 TSX 和纯视觉 CSS 分别采用“真实 macOS 或 macOS 镜像”判断，覆盖整栏 0 宽隐藏、52px 顶带、`shell.leading` 三个恢复控件、196px 安全区、右栏 inset、侧栏与菜单材质。镜像普通窗口可加入无交互的三点灯装饰以保持空间参照，不伪造窗口动作。
- 快捷键 runtime、原生 drag watcher、`-webkit-app-region`、preload、Host paths、目录桥和真实 `data-fullscreen` 绝不跟随镜像标记。Web 继续显示真实 Web 快捷键，不伪装 `dshDesktop`。
- 修复 Noven Web 启动入口：从脚本自身定位仓库，显式固定 `DSH_HOME`、`NOVEN_HOME`、`NOVEN_PROJECTS_ROOT` 和端口，复用同一 Noven 默认功能 patch；已有实例只复用，失败即停，不循环启动。
- 增加一份双端差异表：原生 vibrancy、原生全屏、系统菜单、Dock/托盘、关窗保活、协议、文件拖入路径、目录对话框焦点、下载 UI、签名/Gatekeeper 等分别标明“可镜像／有差异／不可由 Web 验收”。

## 4. 风险与预案

1. **误把 Web 标成真实 darwin，导致快捷键或原生桥启动失败**：呈现标记与运行平台分离，并加负向测试，证明镜像不会创建或要求 Electron bridge。
2. **恢复旧入口时复活双树、双顶栏或双层画布**：先统一功能打开命令和 selfChrome 职责，再恢复可见性；按 Agent／手作 × 空白／已有 × 展开／折叠矩阵验收。
3. **动效造成终端重挂、输入丢失、浮层错位或快速切换残影**：稳定 DOM、单一协调器、临时 transform 完整清理、overlay/resize/fullscreen 降级及中断回归。
4. **测试污染真实数据或重复启动实例**：只用隔离 Web 三根；不重置真实数据。打包前如需关闭当前旧 Test，只处理这一套候选；正式 Noven 不动，不重复安装。
5. **把“完全同步”误报成原生能力完全等价**：只承诺共享 renderer 与普通窗口呈现镜像；真实 Mac 视觉、原生全屏、HID 拖拽、签名和发布链仍单独验收。

## 5. 汇报线与自决线

**必须停下汇报的情况**：需要伪造原生能力才能继续；必须改变刚确认的 Agent／手作信息架构；需要读取新凭据、重置真实数据、装入 `/Applications`、公开发布；或实现结果明显偏离上述顶栏与运动模型。

**我自行决定并事后报备的内容**：组件拆分、共享 helper、具体图标与菜单位置、token 内的时长/曲线、测试组织、双语措辞、parity 文档、构建产物清理，以及不改变业务语义的重构。

## 6. 向上建议：不把“更多动效”误当“更好动效”

重点投资一次清楚的“对话与画布真实换位”和连续折叠，让所有控件服从这套空间语言；不给每个按钮都加弹跳，也不为追求截图一致去伪造 macOS 能力。Web 应成为可信的高保真镜像，而不是另一套需要长期追赶 PC 的产品。
